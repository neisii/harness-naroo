# 환경값 정의 — 이 하네스를 내 환경에 맞추는 법

> 이 문서는 공개 `rules/`(향상된_AI-DLC 12단계)를 **다른 팀·환경에서 쓸 때 갈아끼우는 값**을 한곳에 모은 설정 페이지다. 규칙 문장을 일일이 고치지 않고, 여기 적힌 값만 내 환경 값으로 바꿔 읽는다.

## 왜 이 문서가 있나 (요리책 비유)

규칙 문서는 **요리책**과 같다. 이 요리책은 원래 한 팀(어느 폐쇄망 SI의 차세대 사업)에 딱 맞게 쓰였다. 그래서 "그 팀 전용" 부분이 두 종류 섞여 있다.

1. **이름표** — "CJ 설탕"처럼 브랜드 이름일 뿐인 것. 자리에서 "설탕"으로 고쳐 쓰면 문장이 그대로 멀쩡하다. 규칙에서는 폴더 경로나 `화면ID` 같은 식별자가 이에 해당하며, 이미 플레이스홀더(`<워크스페이스>` 등)로 바꿔 두었다.
2. **책 전체에 밴 전제** — "넌 늘 김치찌개를 만든다"처럼 모든 줄에 박힌 가정. 남이 볶음밥을 만든다고 "김치찌개"를 전부 "요리"로 바꾸면, 끝도 없고 문장이 "요리를 간 봐라"처럼 속 빈 맹탕이 된다. 그래서 전수 교체하지 않는다. 대신 **이 설정 페이지에 "이 팀은 이렇게 쓴다"를 모아 두고, 규칙 본문은 구체적인 예시로 그냥 둔다.**

**원칙:** 규칙의 구체 값을 지우지 않는다. 그 자리의 값은 "이 팀 예시"로 읽고, 내 환경 값은 이 표에서 찾아 바꾼다. 구체 예시가 남아 있어야 규칙이 맹탕이 되지 않는다.

## 갈아끼우지 않는 것 (핵심 원리)

환경이 바뀌어도 이 뼈대는 그대로다. 이게 하네스의 정체성이다.

- 사람 게이트(되돌리기 어렵거나 바깥으로 나가는 일은 사람 확인).
- 검증은 검증으로만 닫는다(검증하지 못한 것을 검증 완료로 쓰지 않는다).
- 비동기 검수(사람 병목을 큐·장부로 흘린다).
- 가역성 분류(거부권 기준은 점수로 못 덮는다).
- 청사진 → 승인 → 구현 → 검증 → 완료보고의 흐름.
- 정보가 명확한 영역만 병렬화한다.

## 갈아끼우는 값 (swap-list)

아래 범주별로 **이 팀 예시 → 내 환경 값 → 규칙이 말하는 역할 → 나오는 곳**을 적는다. 역할만 남기고 값을 바꾸면 규칙은 그대로 돈다.

### A. 경로·워크스페이스

| 플레이스홀더 | 이 팀 예시(원본) | 역할 |
|---|---|---|
| `<워크스페이스>` | `{본인 경로}\IdeaProjects` | 레포들이 체크아웃된 상위 폴더 |
| `<공유문서 루트>` | `…\project_docs\docs` | 세션들이 공유하는 문서·장부·스크립트 루트 |
| `<공유문서 저장소>` | 위 루트의 레포 루트 | 공유 문서 저장소 자체 |
| `<팀구분>` | `team2` | 산출물·브랜치의 팀 세그먼트 |
| `<이름약자>` | `ghbaek` | 산출물·브랜치의 담당자 세그먼트 |

- 규칙은 "산출물은 지정된 산출물 루트에 둔다"처럼 **역할**만 말한다. 산출물 루트·대기 장부 위치·워크스페이스 루트를 내 값으로 정한다.
- `지시대기`·`_작업중` 같은 하위 폴더 이름은 공유문서 루트 내부 구조다. 이름이 달라도 역할(대기 장부 / 작업 중 임시)만 맞추면 된다.
- 정의 정본: `rules/00` 상단 "경로 플레이스홀더(환경값)".

아래 두 경로는 아직 플레이스홀더로 바꾸지 않아 규칙 본문에 원본 그대로 보이지만, 이것도 환경값이다(C·F 일반화 때 정리 예정). 규칙은 그대로 두고 여기서 바꿔 읽는다.

| 규칙에 보이는 원본 | 역할 |
|---|---|
| `{본인 경로}\.prj-ai-metrics\<프로젝트>` (12단계) | 저장소 밖에 두는 작업 메트릭 원장 위치(자동커밋 방지). 내 환경의 "저장소 밖 원장 루트"로 읽는다. |
| `{본인 경로}\.claude\secrets\devdb_readonly.env` (6단계) | 개발DB 접속정보 등 비밀 파일 위치. 값 자체는 대화·문서·메모리에 남기지 않는다(10단계 TS-11). |

### B. 브랜치·역할·팀 이름

- **브랜치 스킴:** 구조 `<팀구분>/<이름약자>/<작업ID>`는 유지하고 값만 바꾼다. 예: `your-teamname/ghbaek/asas-112`. 원본의 SI 특유 요소(`_dev` 접미사, 작업 단위를 화면으로 한정한 부분)는 걷어냈다. `작업ID`는 일반 이슈·작업 식별자다.
  - 단, 규칙 본문(특히 8·12단계)의 예시 브랜치에는 아직 `_dev`가 보일 수 있다(예: `team2/ghbaek_dev/...`). 이 팀 예시이니 `_dev` 없이 읽는다.
- **역할 이름:** "결정자 / 검수자 / 구현자"라는 **개념은 핵심**이고, 이름은 환경값이다. 이 팀 예시 `qa-master`·`scenario-master`·`*-developer`를 내 조직의 역할 이름으로 바꾼다.

### C. 스택·빌드·서버

핵심은 "구현한 뒤 빌드하고 검증한다"이지 특정 빌드 도구·프레임워크가 아니다. 아래는 이 팀 스택(Java·Spring·Gradle·MyBatis·Flyway) 어휘가 규칙에 박힌 자리다. 내 스택의 대응물로 읽는다.

| 이 팀 예시 (규칙 출현) | 규칙이 말하는 역할 | 내 환경에서 |
|---|---|---|
| `gradlew`·`bootRun` (12·11단계, 13+줄) | 빌드·서버 기동 명령 | 내 빌드·실행 명령(`npm run`·`make`·`mvn` 등) |
| `ArchitectureTest`·`FeignClient`·core 파일 (10·12단계) | 스택 고유의 아키텍처 검증·서비스 연동 | 내 스택의 대응 검증·연동 방식(없으면 그 규칙 줄 생략) |
| `application-local.yaml`·`logback-spring.xml`·`gradle.properties` (11단계 CS-09) | 로컬 설정·로깅·빌드 속성(커밋 제외) | 내 스택의 로컬 설정·비밀·빌드 파일 |
| MyBatis `mapper/`·Flyway `db/migration/` (11단계) | 영속성 매핑·DB 마이그레이션 | 내 ORM·마이그레이션 도구의 대응 경로 |
| WT-10 포트(로컬+10000) | 로컬 서버 포트 배정 규칙 | 내 포트 배정 규칙 |
| `memcheck`의 Java 프로세스 | 기동 전 메모리 점검 대상 | 내 런타임 프로세스(JVM·Node 등) |

- 바꾸지 않는 핵심 원리: "빌드 산출물·로컬 설정·비밀·대용량 바이너리는 커밋하지 않는다", "기동 전 자원을 점검한다", "구현 후 검증한다". 도구 이름만 환경값이다.

### D. 소스 헤더·사내 보안도구

- 원본의 `@programId`/`@processId` 헤더, `NPROTECT`·`ANYID`(사내 보안 에이전트)는 특정 조직 전용이다.
- 조직 고유 헤더·보안 토글이 있으면 같은 자리에 내 것을 넣고, 없으면 그 규칙 줄은 적용하지 않는다(조건부·선택).

### E. 작업 모델 — "화면 단위"라는 전제 (핵심 난제)

이게 요리책의 "김치찌개"다. 규칙은 **작업 단위 = 화면(screen)**이라는 가정 위에 쓰였다(`화면`만 91줄). 남이 API·배치·라이브러리를 만든다면 이 어휘를 자기 작업으로 읽어야 한다.

**바꾸지 않는 것(핵심 흐름):** 청사진(48줄) → 승인 → 구현 → 검증 → 완료보고서(18줄). 이 산출물과 흐름은 작업 종류와 무관한 뼈대다. 어휘에 "화면"이 섞였다고 함께 바꾸지 않는다.

**바꿔 읽는 것(도메인 전제):**

| 이 팀 예시 (규칙 출현) | 읽는 법 |
|---|---|
| **화면** (작업 단위, 91줄) | 내 작업 단위(기능·API·배치·라이브러리 등) |
| **화면설계서** (13줄) | 내 작업의 요구 명세·설계 입력 |
| **공통코드**(19줄)·**개발DB**(6줄)·**테이블 명세**(7줄) | 내 도메인의 참조 데이터·스키마 근거 |
| **퍼블리싱**(8줄)·**BFF**(13줄)·**팝업**(12줄) | 프론트 UI 고유 어휘 — 내 작업에 없으면 그 규칙 줄은 적용하지 않는다 |

- 규칙 본문의 "화면"을 전수 치환하지 않는다(그러면 "작업을 간 봐라"처럼 맹탕이 된다). 이 표를 근거로 **읽을 때** 자기 작업으로 바꾼다. E가 범용화의 진짜 중심인 이유가 이것이다.

### F. OS (Windows/PowerShell)

규칙의 OS 특수는 두 갈래다. 섞지 않는다.

**(1) Windows 전용이라 비Windows면 건너뛰는 것 — 260자 경로 제한의 산물.** Windows는 파일 경로가 260자를 넘으면 깨진다. 아래는 그 한 가지 제한 때문에만 있는 우회다.

- 12단계 WT-06 워크트리명 압축
- `core.longpaths=true` git 설정 (WT-03·06)
- WT-15 `\\?\` 접두 경로 + `Remove-Item` 삭제 폴백

OS가 Windows 계열이 아니면 이 우회들은 **적용하지 않고 다음으로 넘어간다**(제한이 없어 무의미하다). OS 판별은 세션 환경 정보(플랫폼)나 `uname`(POSIX)·`$IsWindows`(PowerShell)로 한다.

**(2) 모든 OS에 필요하지만 명령만 다른 것 — 건너뛰지 말고 명령만 바꾼다.**

- 포트 점유 조회 (WT-10 `Get-NetTCPConnection`·`netstat`) → `ss`·`lsof` 등. 포트 확인이라는 절차 자체는 모든 OS에서 한다.
- 경로 구분자 `\` → `/`.
- 영구 삭제는 OS 중립 `safe-delete` 스킬이 이미 대신한다(GL-28).

### G. 프로젝트 목록·포트

규칙 곳곳이 이 팀의 프로젝트와 포트 관행을 예로 든다. 전부 환경값이다.

- **프로젝트:** admin·buy·catalog·contract·member·sell·settlement (각자 담당 세션이 있다, 12단계 WT-10·12·13). 내 조직의 프로젝트·서비스 목록으로 바꾼다.
- **포트:** 워크트리 서버 = 로컬 포트 + 10000 (예: buy 로컬 8090 → 워크트리 18090, 12단계 WT-10·11). 내 포트 배정 규칙으로 바꾼다.
- 역할 이름(qa-master·`*-developer` 등)은 B 참조.

### H. 커밋 귀속 정책

커밋·PR 메시지에 AI 귀속 줄(`Co-Authored-By: Claude …`, "Generated with Claude Code")을 넣을지는 팀이 정한다(5단계 CM-11).

| 항목 | 이 팀 예시(원본) | 내 환경에서 |
|---|---|---|
| 귀속 줄 | 금지 | 정하지 않았으면 Claude Code 기본(넣음)을 따른다. 금지로 정했으면 아래 설정을 넣는다 |
| 출처 끄기 | 설정 `"attribution": {"commit": "", "pr": ""}` | 범위에 맞는 설정 파일에 넣는다(모두에게면 `.claude/settings.json`을 커밋, 나만이면 `.claude/settings.local.json`) |
| git 훅 | —(필수 아님) | 선택. 두고 싶은 팀만 각자 둔다. 하네스는 설정 밖을 통제하지 않는다 |
| `Claude-Run-Id` trailer | 메트릭 훅(`.githooks/prepare-commit-msg`)이 붙임 → `PRJ_METRICS_DIR`를 빈 폴더로 지정해 막음 | **조건부:** 그런 메트릭 훅과 원장이 있는 팀만 해당. 없으면 이 줄은 생길 일이 없으니 건너뛴다 |

- 바꾸지 않는 핵심 원리: "Claude Code가 이미 주는 설정으로 출처를 끄고, 그 밖은 통제하지 않는다." 하네스가 플랫폼 기능을 다시 만들지 않는다.

### I. 대화 언어

규칙과 문서는 한국어로 쓰여 있지만, 하네스는 대화 언어를 정하지 않는다. 한국어 사용자라도 영어나 다른 언어가 편하면 그 언어로 쓰면 된다.

| 항목 | 이 팀 예시(원본) | 내 환경에서 |
|---|---|---|
| Claude와의 대화 언어 | 한국어 | 쓰고 싶은 언어. 정하지 않으면 Claude가 상황에 맞춰 고른다 |
| 정해 두는 곳 | 개인 설정 `~/.claude/CLAUDE.md`에 한 줄 | 같은 곳. 프로젝트 `CLAUDE.md`에 넣으면 팀 전체에 그 언어를 강제하게 되니 넣지 않는다 |

- **이런 일이 있을 수 있다:** 한국어로 대화하다가 어느 순간 Claude가 영어로 답한다. 이 하네스를 만들면서 겪었다(2026-11-20). 맥락이 압축되면 이전 대화가 영어 요약으로 바뀌어 들어오고, 그 직후 응답이 영어로 끌려갔다. 시스템 안내·도구 출력이 영어인 것도 겹친다. 내부 동작을 확인한 건 아니고, 겪은 순서에서 추정한 원인이다.
- **막는 법:** 개인 설정에 언어를 적어 둔다. 이 파일은 압축 뒤에도 매번 다시 읽힌다. 예:

  ```
  ## 대화 언어
  - 나와의 대화는 한국어로 한다. 맥락 압축 요약·시스템 안내·도구 출력이 영어여도 마찬가지다.
  ```

- 바꾸지 않는 핵심 원리: 대화 언어는 개인 선택이다. 하네스는 규칙으로 언어를 강제하지 않는다.

## 읽는 법 요약

1. 규칙에서 플레이스홀더(`<…>`)나 구체 경로·이름·명령을 만나면, 지우지 말고 이 표에서 내 값을 찾아 바꿔 읽는다.
2. "화면" 같은 작업 모델 어휘는 E 항목을 근거로 내 작업 단위로 읽는다.
3. OS가 Windows 계열이 아니면 260자 경로 제한 우회(F-1)는 건너뛴다. 단 포트 조회처럼 모든 OS에 필요한 절차는 건너뛰지 말고 명령만 바꾼다(F-2).
4. 핵심 원리(사람 게이트·검증·흐름)는 바꾸지 않는다.
