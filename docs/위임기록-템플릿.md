# 위임기록 템플릿

> 여러 세션으로 나눠 쓸 때(소규모 모드) 사람이 게이트웨이 세션에 무엇을 맡겼는지 적는 양식이다. 저장소 안에 `위임기록.md`로 두고, 사람이 언제든 고치거나 거둬들인다. 쓰는 법은 [`오케스트레이션-구성.md`](./오케스트레이션-구성.md) 2걸음. 설계 근거는 `design-notes/10-오케스트레이션-구성층.md` D-2·부록 A.

두 부분으로 되어 있다.

- **기본(필수):** 게이트웨이에 코디네이션 역할만 맡긴다. 게이트 승인은 전부 사람이 한다.
- **좁은 위임(선택):** 일부 게이트를 게이트웨이가 검증을 거친 뒤 대신 승인한다. 켤 때만 아래 "위임한 게이트" 절을 더한다.

규칙은 하나다. **목록에 없는 건 전부 사람에게 올린다.**

````markdown
# 위임 기록 (orchestration)

- 저장소:
- 게이트웨이 세션:
- 실무자 세션:
- 기록 시작: YYYY-MM-DD
- 모드: 소규모 — 전용 QA 세션·대기 장부·순찰 없음, 사람이 결정 창구

## 사람이 게이트웨이에 위임한 것 (코디네이션 역할)
- [ ] 실무자 세션 생성·종료 (모델·권한 모드·지시문 3줄)
- [ ] 사람의 승인을 원문 그대로 실무자에 전달
- [ ] 실무자 상태·진행 감시, 막히면 사람에게 보고

## 위임하지 않은 것 (사람이 직접 결정)
- 청사진 승인(GT-02)
- 커밋 계획 승인(CS-01)·요구사항과 결과 대조(CM-01)  ← 좁은 위임을 켜면 아래 절로 옮긴다
- push · PR · 병합
- 되돌리기 어려운 git 명령(CS-06)
- 업무 결정, 그 밖에 규칙이 [사람 확인]으로 정한 지점 전부

## (선택) 위임한 게이트 — 좁은 위임
- [ ] 커밋 계획 승인(CS-01)
- [ ] 요구사항과 결과 대조(CM-01)
- 조건: 게이트웨이의 직접 확인 + 새 맥락 재검증을 둘 다 통과해야 승인한다.
  하나라도 통과하지 못하면 근거째 사람에게 올린다.
- 게이트웨이의 승인은 아래 "결정 기록"에 근거(검증 결과 포함)와 함께 남긴다.

## 1회 지시 기록
- 위 목록 밖의 일을 사람이 그때만 맡긴 경우(예: "이번 PR은 네가 병합해").
  그 건에 한해 실행하고, 상시 권한으로 늘려 잡지 않는다.

## 결정 기록
| 일시 | 무엇 | 누가 | 근거 |
|---|---|---|---|

## 근거·번복
- 근거: 사람의 지시 원문 "<원문>" (일시)
- 상태: 유효 / 번복됨(<일시·사유>)
- 사람은 언제든 이 위임을 거둬들인다. 게이트웨이는 "위임한 것" 밖의 모든 결정을 사람에게 올린다.
````

## 어떤 게이트를 위임할 수 있나

임의로 고르지 않는다. 가역성 기준(`reversibility-gate`의 기준 4개)을 게이트에 적용한 결과다.

| 게이트 | 위임 | 이유 |
|---|---|---|
| 커밋 계획 승인(CS-01) | 가능 | push 전이라 되돌릴 수 있고, 규칙으로 확인할 수 있다 |
| 요구사항과 결과 대조(CM-01) | 가능 | 청사진과 코드·테스트를 맞춰 보는 일이라 규칙으로 확인할 수 있다 |
| 청사진 승인(GT-02) | 사람 | 설계 판단이 들어간다 |
| push · PR · 병합 | 사람 | 되돌리기 어렵고 바깥으로 나간다 |
| 되돌리기 어려운 git(CS-06) | 사람 | 되돌릴 수 없다 |
| 업무 결정 | 사람 | 사람이 정할 일이다 |
