# session-wake — 세션 이름으로 복사본 없이 깨우기

번들 스크립트: `${CLAUDE_PLUGIN_ROOT}/skills/session-wake/session_wake.py` (Python 3, 표준 라이브러리만 사용)

## 먼저: 별도 세션이 필요한 일인가

Claude Code에서 다른 AI에게 일을 맡기는 방법은 둘이다. 이 스킬은 둘째(별도 세션)를 다룬다.

| | 서브에이전트 (`Agent` 도구) | 별도 세션 (`claude --bg`, 이 스킬로 깨움) |
|---|---|---|
| 정체 | 지금 세션이 띄우는 하위 작업 | 독립된 Claude Code 세션. `claude agents` 목록에 이름으로 보인다 |
| 결과 | 끝나면 결과를 띄운 세션에 보고한다 | 스스로 일하다 게이트에서 멈추고, 메시지로 보고하며 기다린다 |
| 다시 지시 | 띄운 세션만 그 ID로 이어서 보낸다 | 어느 세션이든 이름으로 SendMessage한다. 꺼졌으면 이 스킬로 깨운다 |
| 권한 | 띄운 세션의 권한 설정 안에서 돈다 | 띄울 때 정한 기동 옵션(모델·권한 모드·금지 도구)을 따르고, 깨울 때도 되살아난다 |
| 사람이 직접 보기 | 띄운 세션을 거쳐서만 | 사람이 그 세션에 직접 붙어 대화하고 승인할 수 있다 |
| 맥락 | 띄운 세션의 맥락을 물려받지 않는다(지시문만 받음) | 물려받지 않는다 |

**권장**
- **서브에이전트:** 한 번에 끝나고 결과만 받으면 되는 일. 예: 조사, 새 맥락 재검증(`dlc-gate`의 독립 재검증), 범위가 분명한 구현 조각.
- **별도 세션:** 청사진 → 승인 → 구현 → 커밋처럼 사람의 게이트를 여러 번 오가는 일, 사람이 중간에 직접 승인하거나 대화해야 하는 일, 자기 브랜치·워크트리를 갖고 오래 일하는 실무자. 여러 세션을 엮는 구성은 `docs/오케스트레이션-구성.md`를 따른다.
- 애매하면 서브에이전트로 시작한다. 게이트를 오가야 한다는 게 드러나면 별도 세션으로 옮긴다.

## 이 스킬이 있는 이유

별도 세션을 다시 살리는 기능 자체는 Claude Code가 준다(`claude --bg --resume`). 하네스는 그 기능을 다시 만들지 않는다. 다만 그대로 쓰면 실전 검증(2026-11-16~20)에서 겪은 함정에 빠진다. 이 스킬은 그 함정만 막는다.

- 살아 있는 세션을 다시 `--resume`하면 **복사본**이 생겨 같은 이름이 둘이 되고, 메시지가 엉뚱한 쪽으로 간다. → 살아 있으면 깨우지 않고, 복사본이 생기면 바로 정리한다.
- 목록의 `state=done`은 종료가 아니다. 턴을 끝내고 지시를 기다리는 살아 있는 세션도 `done`이다. → 살았는지는 `pid`로 본다(`session-stall-check`가 같은 기준으로 판정).
- 같은 이름의 기록이 여럿 남는다. → 가장 최근 기록의 전체 sessionId로만 깨운다.

## 사용법
```
python ${CLAUDE_PLUGIN_ROOT}/skills/session-wake/session_wake.py <세션명> [--dry-run]
```
`--dry-run`은 판단까지만 하고 resume을 실행하지 않는다.

## 동작
1. `claude agents --all --json`(배열)에서 이름이 같은 레코드를 모으고 `startedAt`이 가장 큰 것을 고른다.
2. 같은 이름 레코드 중 `pid`가 있는 것이 있으면 resume하지 않고 `[이미 떠 있음]`을 출력한다. 이때는 그 세션에 SendMessage로 바로 지시한다. `state` 값은 보지 않는다.
3. `pid`가 없으면 그 레코드의 **전체 sessionId**(UUID)와 `cwd`로 `claude --bg --resume <전체 sessionId>`를 실행한다. 짧은 id는 쓰지 않으며, UUID가 아니거나 `cwd`가 없으면 중단한다.
4. 출력에 `started a copy as <newId>`가 있으면 원본이 실제로는 살아 있었다는 뜻이다. 그 복사본을 즉시 `claude stop <newId>`로 종료하고, 원본 이름으로 SendMessage하라고 안내한다. 복사본에는 보내지 않는다.
5. `note: woke session ...`만 있고 복사본 note가 없으면 정상 재개다. 같은 id·이름으로 복귀하며 기본 시작 프롬프트와 `--disallowedTools`는 다시 넣지 않는다(최초 기동 옵션이 자동으로 재적용된다). 실측(2026-11-19, 2.1.328): 기동 옵션은 `~/.claude/jobs/<id>/state.json`의 `respawnFlags`에 저장되고, 깨울 때 note에 `woke session … with its saved options (-n, --permission-mode, --disallowedTools, --model)`처럼 다시 적용한 옵션이 그대로 나온다. note에 옵션이 셋뿐이면 처음부터 그 셋으로 띄운 세션이다.
6. 마지막에 같은 이름 레코드를 다시 조회해 건수를 보고한다. 1건이 아니면 경고한다.

프로세스를 직접 종료하지 않는다(`claude stop`만 쓴다). 이름이 아예 없으면 `[없음]`을 출력하고 종료 코드 3을 돌려준다. 이때는 `claude --bg`로 새 세션을 띄운다.

종료 코드: 0 정상(이미 떠 있음·깨움·복사본 정리), 2 사용법·입력 오류, 3 이름 없음, 4 재개 실패.

## 알아둘 점
- 깨운 직후 몇 초 동안은 `pid`가 조회에 나타나지 않아 마지막 줄이 `pid` 없이 나올 수 있다. 다시 호출하면 `[이미 떠 있음]`으로 보인다.
- 종료한 복사본 레코드가 목록에 남아 같은 이름이 2건으로 보일 수 있다. 그러면 SendMessage 전에 이름이 유일하게 해석되는지 확인한다.
