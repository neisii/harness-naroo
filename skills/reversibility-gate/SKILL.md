# reversibility-gate — 혼자 할까 / 물어볼까 (가역성 판정)

정본 규칙: `design-notes/07-가역성분류표.md`. 이 스킬은 그 규칙의 **실행 가능한 라우터**다.

기준 4개를 self-assess하면 결과 4개 중 하나로 보내고, **판정 근거**를 남긴다:

- **A 자율 실행** — 그냥 한다
- **B 사후 검수 + 알림** — 먼저 하고 장부에 남긴 뒤 사람이 나중에 본다
- **C 사전 승인** — 멈추고 사람 승인을 받는다
- **D 보류·질의** — 뭘 하란 건지 몰라 못 정한다 → 옆으로 치우고 다음 일부터(03 제쳐-당김)

## 실행

```sh
python3 "${CLAUDE_PLUGIN_ROOT}/skills/reversibility-gate/reversibility_gate.py" \
  --task "무슨 일인지 한 줄" \
  --reversibility 가역|비가역 --rollback 있음|없음 \
  --clarity 명확|모호 --business 해당없음|사업결정 --scope 내구역|외부공유 \
  [--confidence 높음|보통|낮음] [--json --session <세션명> --why-business "..."]
```

| 기준(인자) | 뜻 | 값 |
|---|---|---|
| `--reversibility` | ① 되돌릴 수 있나 | 가역 / 비가역 |
| `--rollback` | 되돌리는 방법이 실제로 등록됐나 | 있음 / 없음 |
| `--clarity` | ② 뭘 하란 건지 확실한가 | 명확 / 모호 |
| `--business` | ④ 사람이 정할 사업 결정인가 | 해당없음 / 사업결정 |
| `--scope` | ③ 내 구역인가, 외부·공유인가 | 내구역 / 외부공유 |
| `--confidence` | 자기 판단 확신도 | 높음 / 보통 / 낮음(한 단계 보수적) |

## 길 정하는 순서 (점수 합산 금지)

```
STEP 1 — 거부권 (하나라도 걸리면 끝):
   ② 모호 → D · ④ 사업 결정 → C · ① 비가역 → C
STEP 2 — ③ 영향범위로 조절:
   내 구역 → A · 외부·공유 & 롤백 없음 → C · 외부·공유 & 롤백 있음 → B
확신도 낮음 → 한 단계 보수적(A→B→C).
```

**핵심:** 거부권은 다른 기준이 아무리 안전해도 혼자 못 덮는다. "되돌릴 수 있고·명확하고·내 일 같아도" 사업 결정이면 C다.

## 판정 근거 기록 (AG-15 호환, 독립)

`--json`이면 사후 감사용 레코드를 낸다(07의 규격). 장부를 쓰면 그대로 넣어 순찰·검수 흐름에 띄우고, 안 쓰면 JSON 파일로만 남겨도 된다 — 판정 자체는 장부가 필요 없다. `--why-*`로 기준별 근거를 채운다(비면 사후 감사 가치가 낮다는 경고).

```json
{
  "종류": "가역성판정", "작업": "...", "결과": "A|B|C|D",
  "판정시각": "YYYY-MM-DD HH:MM", "세션": "...",
  "기준": { "가역성": {"값":"...","롤백경로":"...","근거":"..."}, "기반정보": {...},
           "영향범위": {"값":"...","판정방식":"자가","근거":"..."}, "업무규칙": {...} },
  "확신도": "...", "거부권발동": "①|②|④|없음", "보수조정": false, "결정근거": "..."
}
```

## 한계 (정직하게)

- ③ 영향범위를 지금은 **자가 입력**으로 받는다. 07의 "worktree·sparse 범위로 자동 판정"은 아직(장부·환경 연동은 하네스 구성 시).
- 입력이 느슨하면 거부권이 무력화된다(쓰레기 입력=쓰레기 판정). 그래서 **근거 기록이 짝** — 사람이 사후에 "이건 네가 정하면 안 됐는데"를 잡아낸다.
- `--selftest`로 라우팅 자기 점검(07 데모 5개 케이스). 예시는 `examples/reversibility_demo.py`.
