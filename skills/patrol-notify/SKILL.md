# patrol-notify — 사람 응답 대기 백오프 알림

정본: 6단계 `${CLAUDE_PLUGIN_ROOT}/rules/향상된_AI-DLC_6단계-Agent간소통규칙.md` (AG-15).
원본 `patrol-notify.ps1`의 **크로스플랫폼 구현**이다. 원본은 대기 장부 집계 도구를 직접 호출했지만, 이 판은 **상태 JSON을 입력으로 받는다**(데이터 소스와 알림 로직 분리). 알림은 `os-notify` 스킬을 호출한다.

## 사용법

```sh
python3 "${CLAUDE_PLUGIN_ROOT}/skills/patrol-notify/patrol_notify.py" --status-json status.json   # 평소 — 순찰 루프 틱마다 호출
cat status.json | python3 "${CLAUDE_PLUGIN_ROOT}/skills/patrol-notify/patrol_notify.py"           # stdin 입력
python3 ".../patrol_notify.py" --status-json status.json --dry-run                                # 알림·상태 갱신 없이 due 항목만 출력
python3 ".../patrol_notify.py" --mark-sent <KEY> [<KEY> ...]                                      # 회신추정 항목 발송 기록
```

| 옵션 | 의미 |
|---|---|
| `--status-json <파일>` | 상태 JSON 파일(생략하면 stdin, `-`도 stdin). `--mark-sent` 에는 불필요 |
| `--state-path <파일>` | 백오프 상태 파일. 기본 `~/.claude/patrol-notify/state.json`, 환경변수 `PATROL_NOTIFY_STATE`로도 지정 |
| `--dry-run` | 알림을 보내지 않고 상태도 쓰지 않는다(테스트용) |
| `--mark-sent KEY...` | 회신추정 항목을 "발송함"으로 기록 |

종료 코드: 0 정상(알림 실패 경고 포함), 2 입력 오류(상태 JSON 읽기 실패 등).

## 입력 스키마 (상태 JSON)

최상위 객체의 세 배열을 소비한다(없으면 빈 배열로 본다). 키는 한글 그대로다.

```json
{
  "사람응답대기항목": [
    {"세션": "sess-a", "요지": "승인 요청", "경과분": 130, "묶음": "B1", "보낸시각": "2026-11-07 10:00"}
  ],
  "보류재개대기항목": [ {"묶음": "B1"} ],
  "열린항목": [
    {"세션": "s1", "요지": "작업 X", "보낸시각": "2026-11-06 09:00", "요청자": "req-sess", "수신자": "rcv-sess",
     "사전확인": {"판정": "회신추정", "근거": "수신자 회신 흔적"}}
  ]
}
```

| 배열 | 소비하는 필드 | 용도 |
|---|---|---|
| `사람응답대기항목[]` | `세션`, `요지`, `경과분`(분, 숫자 또는 null), `묶음`(선택), `보낸시각` | 백오프 알림 대상(재개 주체가 사람인 대기 항목) |
| `보류재개대기항목[]` | `묶음` | "같은 묶음 N건 대기" 계산(사람 응답 대기 포함 전체 건수) |
| `열린항목[]` | `세션`, `요지`, `보낸시각`, `요청자`, `수신자`, `사전확인{판정, 근거}` | `사전확인.판정 == "회신추정"` 인 항목만 3T 병행 발송 대상 |

`경과분`이 null/없는 항목은 경과를 계산할 수 없으므로 추측하지 않고 건너뛴다.

## 동작

- 항목 키는 `세션::요지`. 항목별 누적 경과(분)가 임계값을 넘으면 due. 임계값은 이미 보낸 알림 횟수에 따라 120 / 240 / 480 / 960분씩 누적(2h → 6h → 14h → 30h)되고, 5차 이후는 1440분(24h)씩 더해진다. 고정 반복 대신 간격을 늘려 알림 피로를 줄인다.
- 같은 틱에서 동시에 due인 항목은 `os-notify` 호출 1번으로 묶는다. 표시는 경과시간 내림차순 상위 3건 + 넘치면 `...외 N건`. 제목은 `[사람 응답 대기] N건`.
- 레벨: 이미 보낸 횟수의 최댓값이 0회=Info, 1~2회=Warning, 3회 이상=Error.
- 같은 `묶음`의 다른 항목 수는 `, 같은 묶음 N건 대기`로 덧붙인다.
- 알림은 `os-notify/os_notify.py`를 이 스크립트 기준 상대경로(`../os-notify/`)로 같은 파이썬 인터프리터로 실행한다. 인자를 리스트로 직접 넘겨 요지의 따옴표·줄바꿈이 인자를 쪼개지 않는다. **호출이 실패하면 알림 횟수·시각을 갱신하지 않아 백오프가 진행되지 않는다.**
- 상태 파일(`항목`: 알림횟수·마지막알림시각, `회신추정확인`)은 임시파일에 쓴 뒤 rename하는 원자적 쓰기다. 읽기/파싱에 실패하면 경고하고 빈 상태로 시작한다(알림이 중복될 수는 있어도 영원히 안 가는 것보다 안전). 더 이상 대기 중이 아닌 항목은 알릴 게 없는 틱에도 매번 정리한다.

## 회신추정 3T 항목의 병행 발송 (AG-15)

`열린항목`의 `사전확인.판정`이 `회신추정`인 항목은 사람 에스컬레이션 대신 qa-master 정보 알림으로 낮추고, 요청자에게도 '장부 종결 여부 확인'을 보낸다(정보 전달, 구현·결정 요청 아님). 이 스크립트는 세션에 메시지를 보낼 수 없으므로 매 실행마다 `KEY: <10자 ID>`와 `SEND-TO <대상>: <문안>` 줄을 출력하고, 순찰 세션이 보낸 뒤 항목마다 `patrol_notify.py --mark-sent <KEY>`로 기록한다. 기록된 항목은 다시 출력하지 않고, 더 이상 회신추정이 아닌 항목은 상태에서 정리한다. KEY는 `세션::요지::보낸시각`의 sha1 앞 10자다. 순찰은 요청자 대신 재요청·결정하지 않는다.

## 전제·한계

- 단일 순찰 인스턴스를 전제한다(동시 실행 시 상태 파일 갱신이 겹칠 수 있음).
- 항목 식별 키는 `세션::요지`라서 요지 문구가 바뀌면 새 항목으로 취급돼 백오프가 처음부터 다시 시작된다.
- `os-notify`는 알림 수단이 없으면 stdout으로 폴백하며 이때도 성공(종료 코드 0)으로 끝난다. 그래서 실제 화면 알림이 떴는지는 이 스크립트가 보장하지 않는다.
