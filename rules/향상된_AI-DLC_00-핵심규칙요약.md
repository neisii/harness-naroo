# 00 · 핵심 규칙 요약

> **목적:** 12개 단계 문서의 색인이자 요약이다. 정본은 각 단계 문서이며, 이 요약과 정본이 다르면 정본을 따르고 차이를 사람에게 알린다.
> **원칙:** 이 문서에는 규칙의 새 내용을 쓰지 않는다. 규칙을 바꿀 때는 정본만 고치고, 이 요약은 한 줄 요지와 ID만 맞춘다.
> **강조 표기:** 단계 문서의 규칙은 모두 필수다. **[사람 확인]**은 사람의 명시적 확인 없이 넘어가지 않는 지점에만 붙인다. 2단계 RL-12 위임 범위의 지점은 qa-master의 승인·확인이 사람의 것으로 인정된다.
> **표현:** "알린다"는 사람에게 전하고 기다리지 않고 진행한다는 뜻이다. "확인받는다"·"승인받는다"는 답을 받을 때까지 진행하지 않는다는 뜻이다.
> **경로 플레이스홀더(환경값):** `<워크스페이스>` = 레포들이 체크아웃된 상위 폴더(원본 환경 예: `{본인 경로}\IdeaProjects`). `<공유문서 루트>` = 세션들이 공유하는 문서·장부·스크립트 루트(원본 예: `…\project_docs\docs`). `<공유문서 저장소>` = 그 레포 루트. `<설문 루트>` = 사람에게 묻는 설문을 모아 두는 폴더(기본값 `docs/surveys/`, `survey-gen` 스킬이 관리). 이 값들은 조직·환경마다 다르므로 **네 환경 값으로 바꿔 읽는다**(1단계 GL-29 계열의 환경값).
> **환경값 전체 목록(읽는 법):** 경로 외에 브랜치 스킴·세션 이름(총괄·워커)·스택·빌드 명령·OS·작업 단위("화면") 등 조직마다 바꿔 읽을 값은 레포의 `docs/환경값-정의.md`에 모아 두었다. 규칙 본문의 구체 값(폴더·도구·"화면" 등)은 지우지 말고 **"이 팀 예시"로 읽고, 내 환경 값은 그 문서에서 찾아 바꾼다**. 핵심 원리(사람 게이트·검증·흐름)는 바꾸지 않는다.

## 1. 읽는 방법

1. 사람이 화면/기능 구현을 지시하면 이 문서를 처음부터 끝까지 읽는다. 구현 지시를 받지 않는 `*-master` 세션(qa-master, scenario-master 등)은 시작할 때 2단계 RL-12를 읽는다.
2. 아래 2장 표의 "진입 조건"에 해당하는 행동을 하기 **직전**에 그 단계 문서를 Read 도구로 처음부터 끝까지 읽는다. 같은 세션에서 이미 읽은 문서의 재독은 1단계 GL-27을 따른다(원칙은 다시 읽지 않되 커밋 계획 직전·구현 승인 직전·컨텍스트 압축 뒤 그 단계 행동 때는 다시 읽는다. 규칙 변경 알림을 받은 문서는 이미 읽었어도 다시 읽는다. 서버 기동·병합을 하지 않는 세션은 서버·병합 전용 변경에 한해 재독을 면제한다, 2단계 RL-12).
3. 단계 문서 끝의 "체크리스트"로 그 단계를 마쳤는지 스스로 확인한다.
4. 자기 장부(`지시대기\대기현황\<세션명>.json`)에 open 항목이 있는 세션은, 아래 '가벼운 요청' 예외와 무관하게 새 턴 시작 직후·회신 의존 후속 작업 전·마무리 직전에 6단계 AG-15에 따라 조회한다. 재시작·컨텍스트 압축 후에도 마찬가지다(이미 읽었다는 이유로 생략하지 않는다). 조회 시점·생략 조건은 6단계 AG-15를 따른다.

단순 질의응답·탐색·오탈자 수정 같은 가벼운 요청에는 이 절차(1~3)를 적용하지 않는다.

## 4. 항상 지키는 금지 사항

| 금지 사항 | 정본 |
|---|---|
| 지정된 프로젝트와 WT-02로 만든 브랜치 밖을 수정하지 않는다. 다른 프로젝트 변경이 필요하면 먼저 확인받는다. | GL-01~05 |
| 업무 규칙·기획 의도를 추측하지 않는다(RL-12 위임 범위에서 qa-master가 근거를 기록해 확정하는 것은 예외). 문서와 코드/DB가 다르면 한쪽을 정답으로 고르지 않고 차이를 제시해 확인받는다(테이블·컬럼은 예외: 명세 기준으로 진행하고 차이를 알린다, RQ-03). | GL-16~19, RL-12 |
| 검증하지 못한 것을 검증 완료로 쓰지 않는다. 테스트하지 못한 CASE는 기록한다. | GL-20, GL-25, TS-07 |
| 타 프로젝트 소스·DB를 직접 열람하지 않는다(공용 내부망 개발DB 읽기 전용 SELECT는 사전 승인되어 예외). | AG-08 |
| 다른 Agent에게 구현을 위임하지 않는다. 정보 교환만 한다. | AG-09 |
| 산출물 폴더(`docs/<팀구분>/...`)와 추적 제외 목록의 파일을 커밋하지 않는다. 소스 프로젝트의 미추적 `docs/` 파일(`docs/api/` 등)은 로컬 유지하고, `<공유문서 저장소>` 직속은 커밋 대상이 아니다(`<공유문서 루트>\{admin,buy,contract,member,sell}`는 각 `prj_*\docs`로 연결된 junction이라 같은 폴더이며 위 `docs/` 규칙을 따른다). | AR-01, CS-09 |
| 원격에서 바뀐 설정 파일(yaml·properties)은 원격을 기본값으로 하고, 로컬 구동에 필요한 옵션만 fetch 뒤 다시 적용한다(조직 고유 보안 토글, 예: NPROTECT·ANYID, 은 RL-12 방식만). | CS-09, RL-12 |
| 직접 구현하지 않는 프로젝트(member·settlement·catalog)의 `.metrics/`는 커밋하지 않고 버린다. | WT-13 |
