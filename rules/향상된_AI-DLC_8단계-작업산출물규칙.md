# 8단계 · 작업 산출물

> **목적:** 화면 단위 작업 산출물(청사진·완료보고서·SQL·결과 파일·E2E 시나리오)의 통합 경로와 작성 규칙을 정한다.
> **언제 읽나:** 산출물이나 SQL 파일을 처음 만들기 직전, 브라우저 자동화로 화면을 캡처하기 직전, 재사용 스크립트를 만들기 직전, 사람이 읽는 md 문서에 파일 링크를 넣기 직전, 인계 문서를 만들거나 새 세션이 인계 문서를 읽기 직전, Mermaid 다이어그램이 있는 사람용 html을 만들기 직전, 여러 번 갱신되는 정본·통합 문서의 변경 이력을 쓰기 직전([00 요약](향상된_AI-DLC_00-핵심규칙요약.md) 2장).
> **이 문서가 정하지 않는 것:** 구현 시작 승인은 [4단계](향상된_AI-DLC_4단계-구현시작과정보조사방법.md) GT-02, 완료보고서 항목은 [5단계](향상된_AI-DLC_5단계-결과물검토및커밋규칙.md) CM-02, `{화면ID}-tests.md` 작성은 [10단계](향상된_AI-DLC_10단계-E2E테스트시나리오규칙.md), 워크트리에서의 경로 처리는 [12단계](향상된_AI-DLC_12단계-워크트리사용규칙.md) WT-07이 정본이다.

## 규칙

### AR-01 · 통합 경로

화면 단위 작업 산출물은 모두 아래 폴더에 둔다.

```
<프로젝트>\docs\<팀구분>\<이름약자>\<화면ID>\
    청사진.md
    완료보고서.md
    {주제}.sql, {주제}2.sql …            (테스트 데이터셋·조사·검증용 SQL)
    {기본 이름}_{쿼리 번호}.txt …        (SELECT 결과)
    {화면ID}-tests.md
```

예: `{본인 경로}\IdeaProjects\<프로젝트 루트>\contract-service\docs\team2\ghbaek\screen-020\`

- 이 폴더(화면ID 폴더) 전체를 커밋/버전 추적 대상에서 제외한다. 로컬 히스토리·감사 트레일 용도다.
- 성격(청사진/완료보고서/SQL/E2E 시나리오)에 따라 경로를 나누지 않는다.
- 화면ID가 없는 작업은 `<화면ID>` 자리에 `<작업명>`을 쓴다(`<프로젝트>\docs\<팀구분>\<이름약자>\<작업명>\`). 작업명은 브랜치명과 같다(7단계 BR-01 예외).
- 워크트리에서 작업할 때는 원본 `<프로젝트>\docs\...` 절대경로에 직접 쓴다(12단계 WT-07).
- scenario-verify 파이프라인(QA 시나리오를 구현 코드와 대조해 검증하는 스킬)의 산출물은 이 통합 경로 대신 `{본인 경로}\IdeaProjects\project_docs\docs\단위테스트\{원본시나리오, 개선시나리오\<타임스탬프>, 검증결과\<타임스탬프>}`를 기준으로 한다(스킬이 정본). 선검증 SQL·결과 파일은 `검증결과\<타임스탬프>\내부기록\<화면ID>\`에 두되 파일 이름만 AR-07~AR-09를 따른다. 내부기록의 수행기록·판정 파일은 `{화면ID}_검증수행기록.md`·`{화면ID}_검증판정.json`이다. 평소 작업은 `단위테스트\…\_작업중`에 덮어쓰고, 업로드본을 확정할 때만(`assemble.py --finalize`) 새 `<타임스탬프>` 폴더를 만든다. 확정된 타임스탬프 폴더는 이후 수정하지 않는다.

### AR-02 · 청사진은 파일로 저장한다

- 3단계 RQ-07에서 정리한 청사진은 채팅 응답으로 끝내지 않고 통합 경로의 `청사진.md`로 저장한다.
- 청사진이 통합 경로에 문서화되지 않은 상태로는 구현을 시작하지 않는다.

### AR-03 · 완료보고서는 항상 작성한다

- 1단계 흐름의 "9. 요구사항 ↔ 결과 대조" 다음에 "10. 완료 보고서 작성"이 오는 순서는 그대로다.
- 화면 규모나 작업 시간과 무관하게 예외 없이 작성한다.
- 통합 경로의 `완료보고서.md`로 저장한다.

### AR-04 · 테스트 데이터셋은 재현 가능한 SQL 파일로 관리한다

- 통합 경로에 `{주제}.sql`로 필요한 만큼 만든다. 파일 이름과 개수는 AR-07~AR-09를 따른다.
- 사람이 직접 실행하거나 전달할 수 있어야 한다.

> 이유: 테스트 데이터셋은 개발DB 검증뿐 아니라 내부망DB의 제3자 테스트에도 똑같이 필요하다.

### AR-05 · INSERT가 있는 파일의 구성 순서

1. Insert 전 상태 확인용 SELECT
2. 테스트 데이터 INSERT
3. Insert 후 상태 확인용 SELECT(의도한 행/컬럼이 반영됐는지 확인할 수 있어야 함)

### AR-06 · 항상 새 데이터셋을 준비한다

- 대상 데이터가 이미 DB에 있어도 재사용하지 않고 새 데이터셋을 준비한다.
- 다른 화면·다른 작업자의 테스트 데이터와 값이 겹치지 않도록 한다.

> 이유: 기존 데이터는 다른 사람의 테스트 부산물일 가능성이 높다. 그 데이터에 의존하면 내 테스트가 타인의 변경/삭제에 영향을 받거나, 반대로 타인의 작업에 영향을 줄 수 있다.

### AR-07 · SQL 파일명

- `{주제}.sql`(한글 가능).
- 같은 주제의 후속 파일은 `{주제}2.sql`, `{주제}3.sql`처럼 숫자 접미어를 붙인다.

### AR-08 · 쿼리 번호

파일 안 각 쿼리 바로 앞 주석에 번호를 단다.

| 파일 유형 | 번호 형식 | 후속 파일 |
|---|---|---|
| 조사용 SELECT 파일 | 연속 번호 `Q1, Q2, …` | 번호를 이어서 매긴다(`인벤토리2.sql`은 Q6부터) |
| insert 전 SELECT → INSERT → insert 후 SELECT 구조 | `{섹션}-{순번}`(`0-1`, `1-1`, 파생 쿼리는 `0-1b`) | 이전 파일의 마지막 섹션 다음 번호부터 이어서 매긴다 |

### AR-09 · 결과 파일

- 파일명: `{SQL 파일명에서 숫자 접미어를 뺀 기본 이름}_{쿼리 번호}.txt`. `Q` 접두어는 뺀다(`Q3` → `_3`). 후속 파일의 번호가 이어지므로 기본 이름이 같아도 겹치지 않는다.
- 내용: SELECT 결과를 CSV 형태(헤더 1행 + 데이터 행)로 저장한다.
- 결과가 없는 쿼리(INSERT, 정리 스크립트)는 결과 파일을 만들지 않는다.
- SQL·결과 파일은 모두 같은 화면ID 폴더에 둔다(AR-01의 커밋 제외가 그대로 적용된다).

예(실제 작업 폴더 `screen-020`의 관행):

```
계약구분x거래구분_테스트데이터_인벤토리.sql      ← 조사용 쿼리 파일 (Q1~Q5)
계약구분x거래구분_테스트데이터_인벤토리_1.txt    ← Q1 결과
...
계약구분x거래구분_테스트데이터_인벤토리_5.txt    ← Q5 결과
계약구분x거래구분_테스트데이터_인벤토리2.sql     ← 2차 쿼리 파일 (Q6~Q9)
계약구분x거래구분_테스트데이터_인벤토리_6.txt    ← Q6 결과 (파일명은 `인벤토리`, `인벤토리2` 아님)
단가계약생성.sql                                 ← INSERT 포함 쿼리 파일 ([0]~[4] 섹션)
단가계약생성_0-1b.txt, 단가계약생성_1-1.txt …   ← 섹션형 번호 결과
```

### AR-10 · 브라우저 자동화로 화면을 캡처할 때는 viewport를 고정한다

- 메인 화면은 캡처 전에 viewport를 1920x1080으로 고정한다(`page.setViewportSize({width:1920,height:1080})` 또는 MCP 실행 옵션). 고정하지 않으면 열려 있는 창 크기만큼만 캡처돼 증거가 잘려 보인다.
- 팝업·모달 화면은 그 화면의 원래 창 크기(예: window.open 크기 1100x760)를 허용한다. 이 경우 메인 화면 viewport를 1920으로 키우려고 팝업 창을 억지로 늘리지 않는다.
- 캡처 직전마다 `window.innerWidth`를 확인한다. 새 탭·새 창·팝업 전환, 페이지 이동 뒤에는 특히 확인한다. 메인 화면은 1900 이상이어야 하고(스크롤바 폭 고려), 아니면 viewport를 다시 고정하고 찍는다. 팝업·모달은 그 화면의 원래 창 크기인지 확인한다.
- 한 화면에 다 들어오지 않는 긴 화면은 `fullPage`로 캡처한다.
- 모달 내부 스크롤은 대상 요소를 `scrollIntoView`한 뒤 캡처한다.
- Playwright MCP를 쓰는 모든 세션에 적용한다(시나리오 검증 외 일반 화면 확인 포함).

### AR-11 · 재사용하는 스크립트는 임시 폴더에 두지 않는다

- 분류 생성기, 데이터 준비, 최종결과 생성기처럼 두 번 이상 쓰는 스크립트는 `{본인 경로}\IdeaProjects\project_docs\docs\scripts\<이름>\`에 둔다(`sscheck`, `api-spec-gen`의 선례).
- 임시 폴더(Temp)에는 일회용 스크립트만 둔다. 임시 폴더는 보존이 보장되지 않는다.
- 화면 단위 산출물(SQL, 결과 파일 등)은 AR-01 통합 경로를 따른다.

### AR-12 · md 문서의 파일 링크 형식

사람이 크롬 MarkView(Markdown Viewer with Mermaid Diagrams, Math & Export 확장)로 읽는 md 문서(인덱스·보고·설문 응답 요약 등)에서 로컬 md 파일을 링크로 가리킬 때는 아래 형식을 쓴다. 전 세션 공통이다.

- 링크 글자에 백틱(`)을 쓰지 않고 경로 구분자는 `/`를 쓴다.
- 링크 대상은 `file:///` 절대 URL이 아니라 그 md 파일 위치 기준 상대 경로로 쓰고, 한글은 퍼센트 인코딩한다.
  - 같은 폴더: `[P/지시대기/x.md](x.md)`(실제 파일명이 한글이면 인코딩한 이름)
  - 상위 폴더: `[P/latest/qa-master.md](../latest/qa-master.md)`
- 이 방식은 사용자가 클릭까지 확인한 해결 방식이다. 백틱과 백슬래시 경로, `file:///` 절대 URL을 쓴 링크는 텍스트로 렌더링됐지만 그 원인(렌더러의 file:// 차단, 링크 글자의 이스케이프 등)은 가르지 못했으므로 단정하지 않는다.
- 전제: 크롬 확장이 `file://` 파일에 접근하려면 확장 설정의 '파일 URL에 대한 액세스 허용'이 켜져 있어야 한다(실제 설정 상태는 확인하지 못했다).

### AR-13 · 인계 문서는 latest 루트에 두고 새 세션은 그것만 읽는다 (사용자 확정 2026-10-25)

- 세션 인계 문서는 `{본인 경로}\IdeaProjects\project_docs\docs\latest\<세션명>.md`에 만드는 것이 원칙이다.
- 새 세션은 항상 `latest` 루트의 자기 `<세션명>.md`를 읽는다. 그 아래 `_이전본_*` 폴더는 보존용이며 새 세션이 참조할 대상이 아니다.
- 인계 문서 머리에 적힌 `이전본: _이전본_…` 경로는 보존 위치 안내로만 허용한다. 그 경로의 문서를 읽도록 지시하는 용도로 쓰지 않는다.
- 인계 문서는 `project_docs` 아래 파일이라 커밋 대상이 아니다(11단계 CS-09).
- **갱신 시점(사용자 확정 2026-10-29):** 인계 문서는 시점 기반으로 갱신한다.
  1. push·병합 같은 마일스톤 직후
  2. AG-15 장부에 약속시각이 30분 이상 뒤인 요청을 등록할 때, 또는 `요청유형: 무거움` 요청을 보낼 때
  3. 세션 재기동 직전(qa-master가 요청)
- **내용:** 현재 브랜치·워크트리·최신 해시, 진행 중 작업, 승인·결정 내역, 미결 질문, 다음 할 일. 장부(6단계 AG-15)에 이미 있는 내용은 요약 + 장부 참조로 대신하고 중복 기록하지 않는다.
- **예외:** 세션이 질문 창 등으로 응답 불가 상태면 qa-master가 대화 기록·장부·git 상태를 근거로 대신 작성할 수 있다.

### AR-14 · Mermaid 다이어그램이 있는 사람용 html (사용자 확정 2026-10-25)

- 사람이 보는 md 문서를 Mermaid 다이어그램이 포함된 html로 만들 때는 `{본인 경로}\IdeaProjects\project_docs\docs\scripts\md2html\md2html_mermaid.py`를 쓴다. html을 직접 짜거나 다른 변환기를 새로 만들지 않는다(재사용 스크립트 위치는 AR-11).
- Mermaid가 없는 문서는 기존 `md2html.py`를 쓴다.
- 만든 뒤 `{본인 경로}\IdeaProjects\project_docs\docs\scripts\md2html\check_render.py`(AR-15)로 다이어그램 오류와 글자 넘침(상자 밖으로 나가는 글자)이 없는지 확인한다. 확인하지 못했으면 확인하지 못했다고 적는다(1단계 GL-20).
- 다이어그램 안 한글 넘침의 원인과 해결 방법은 `md2html_설명.md`에 있다.

### AR-15 · 파이썬 Playwright 사용 조건 (사용자 확정 2026-10-25)

Playwright MCP는 기본 실행이라 세션들이 디스크의 공용 브라우저 프로필을 같이 써서 동시에 열면 한쪽이 막히고, `file://`도 막힌다. 그래서 html 렌더 확인에는 파이썬 Playwright를 쓴다.

1. 사람용 html의 렌더 확인(AR-14)은 Playwright MCP가 아니라 `project_docs\docs\scripts\md2html\check_render.py`(파이썬 Playwright)로 한다. 임시 웹서버를 띄우지 않는다.
2. 실행 중인 서버 화면을 조작하는 시나리오 검증·캡처(AR-10)는 지금처럼 Playwright MCP를 쓴다.
3. 파이썬 Playwright는 설치된 브라우저 채널(chrome-dev, chrome, msedge)만 쓰고 `playwright install`로 브라우저를 내려받지 않는다. 항상 headless·임시 프로필로 띄우고 영구(persistent) 프로필은 쓰지 않는다. 사용자 site-packages를 쓰므로 `python -I`로 실행하지 않는다.
4. 새 파이썬 Playwright 스크립트는 재사용 위치(AR-11)에 두고, 산출물·스크린샷은 공용 산출 폴더에 섞지 않는다(1단계 GL-28 ④).

### AR-16 · 산출물 문서 유형과 파일명 (사용자 확정 2026-10-29)

문서 유형별 파일명과 위치는 아래를 따른다. 목적은 인덱스·통합정리 도구가 유형을 오분류하지 않게 하는 것이다.

| 유형 | 파일명 | 위치 | 정본 |
|---|---|---|---|
| 청사진 | `청사진.md` | AR-01 화면ID 폴더 | AR-02 |
| 완료보고서 | `완료보고서.md`(접두 `완료보고서`로 시작하는 변형 포함, 예 `완료보고서_20261026.md`) | 청사진과 같은 화면ID 폴더 | AR-03 |
| SQL·결과·데이터 | `{주제}.sql`, `{기본이름}_{쿼리번호}.txt`, `.csv` | AR-01 화면ID 폴더 | AR-04~09 |
| 인계 문서 | `<세션명>.md` | `project_docs\docs\latest\` | AR-13 |
| 설문 / 설문응답 | `사용자설문_YYYYMMDD[_N].html` / `설문응답_YYYYMMDD[_N].md` | `project_docs\docs\지시대기\`(완료된 설문 html은 `지시대기\완료설문\`) | 2단계 RL-12, `survey-gen` |
| 조사 | 파일명에 `조사` 포함, 전체 범위를 훑으면 `{대상}_전수조사_YYYYMMDD.md` | 화면 단위면 화면ID 폴더, 여러 화면·프로젝트에 걸치면 `지시대기\` | 이 규칙 |
| 재조사 | `청사진재조사_{프로젝트}_결과_YYYYMMDD.md`, `청사진재조사_대상목록_{프로젝트}_YYYYMMDD.csv` | `지시대기\` | 이 규칙 |
| 결정 로그 | `결정안건.md` | `project_docs\docs\통합정리\` | 이 규칙 |
| 연동 규약 | `EP계약.md`(프로젝트 사이 API의 엔드포인트·요청·응답 약속, 선례: `stampTax-revenueStampIntegration\EP계약.md`) | 해당 작업의 AR-01 화면ID(작업명) 폴더 | 이 규칙 |

- 신규 파일부터 적용한다. 기존 문서는 이름을 바꾸지 않고, 도구가 수작업 매핑 테이블(예: `청사진_분류확정.csv`)로 보정한다.
- 이 파일명 패턴은 권장이다. 지키지 않아도 도구가 매핑 테이블로 보정하며 커밋을 막지 않는다.
- 화면ID 폴더에 두어야 할 완료보고서를 다른 폴더에 두면 AR-01 위반이다.

### AR-17 · 여러 번 갱신되는 정본·통합 문서의 변경 이력 포맷 (사용자 확정 2026-10-29)

1. 대상은 여러 번 갱신되는 정본·통합 문서(용어사전, 통합정리 화면·정책 문서, 파이프라인 개요 등)다. 일회성 보고서와 완료보고서는 제외한다. 인계 문서(AR-13)도 이전본 폴더로 보존되므로 제외한다.
2. 변경 이력은 문서 머리의 `<details>`로 접어 두고(기본 접힘) `일자 | 배치 또는 출처 | 변경 내용` 표를 쓴다. 한 줄에 `/`·`·`로 이어 붙이지 않고, 행을 추가해 날짜순을 유지하며, 한 셀의 항목이 많으면 줄을 나눈다.
3. 머리 표에는 '최근 갱신' 한 줄만 두고, 갱신할 때 그 날짜와 이력 표를 함께 고친다.
4. 기존 문서는 소급하지 않고 다음에 그 문서를 수정할 때 바꾼다.
