# 3단계 · 구현 시작 시점 (요청과 응답)

> **목적:** 사람이 작업을 지시할 때 줄 정보, AI가 조사 결과와 질문을 정리하는 방식, 사람에게 결정을 요청하는 표준 형식, 청사진 양식을 정한다.
> **언제 읽나:** 조사 결과를 정리하거나 사람에게 결정을 처음 요청하기 직전([00 요약](향상된_AI-DLC_00-핵심규칙요약.md) 2장).
> **이 문서가 정하지 않는 것:** 구현 시작 승인은 [4단계](향상된_AI-DLC_4단계-구현시작과정보조사방법.md) GT-02, 청사진 저장 위치는 [8단계](향상된_AI-DLC_8단계-작업산출물규칙.md) AR-02가 정본이다.

## 규칙

### RQ-01 · 이 단계에서는 코딩을 시작하지 않는다

### RQ-02 · 사람이 주는 최소 정보

- 작업ID
- 화면명
- 담당 프로젝트
- 화면설계서 위치(주지 않으면 CLAUDE.md '화면설계서 위치'의 기본 경로를 쓴다)
- 특별히 알고 있는 업무 배경

작업 브랜치는 사람이 주지 않는다. AI가 [12단계](향상된_AI-DLC_12단계-워크트리사용규칙.md) WT-02로 만든다(이름은 7단계 BR-01).

### RQ-03 · 조사 범위와 순서

위 정보와 함께 AI에게 전달하는 프롬프트 예시:

```
이 화면을 구현하기 위해 필요한 문서, 기존 코드, API, BFF, DB, Query/Mapper, 공통 기능, 유사 화면을 조사하고, 구현 전에 사람이 알려주거나 결정하거나 확인해야 하는 사항을 도출해라.

조사 대상:
화면설계서 → CLAUDE.md / 개발가이드 → 유사 화면 → 현재 화면 소스 → BFF → API → Query / Mapper → 테이블 명세 → DB 스키마 → 실제 데이터 → 공통 기능
```

- 공통 기능 중 공통코드(셀렉트/라디오/체크박스 등에 쓰이는 그룹코드+코드값)는 [9단계](향상된_AI-DLC_9단계-공통코드규칙.md)의 조사 대상·절차를 따른다.
- 테이블 명세는 `table-spec-convert` 스킬이 정한 위치의 열람용 최신 파일(타임스탬프가 가장 큰 것)을 읽는다. 위치와 고르는 방법은 스킬 문서가 정본이다. 원본 xlsx는 보지 않는다. 목차 시트에서 화면에 쓰이는 테이블을 찾아 해당 시트만 본다.
- 테이블 명세가 구현 기준이다. DB 스키마·실제 데이터는 명세와 대조하는 용도로 보고, 서로 다르면 명세 기준으로 진행하고 차이를 알린다(1단계 GL-19의 예외). 개발DB 행 데이터는 업무 규칙의 근거로 쓰지 않는다(1단계 GL-16).

### RQ-04 · 조사 결과를 네 가지로 분류하고, 사람에게는 C·D만 묻는다

조사에서 나온 불확실성을 그냥 나열하지 않고 다음으로 분류한다.

| 분류 | 의미 |
|---|---|
| A. 즉시 구현 가능 | 현재 정보만으로 판단 가능 |
| B. 자료 확인 필요 | AI가 문서나 코드를 추가로 확인해야 함 |
| C. 사람 결정 필요 | 여러 안 중 무엇을 고를지 사람이 결정해야 함(2단계 RL-01~05). RL-12 위임 범위는 qa-master가 결정한다 |
| D. 기획 확인 필요 | 업무 담당자에게 확인해야 함. 2단계 RL-12 위임 범위 안의 사항은 qa-master에게 질의해 근거와 함께 확정받을 수 있다(연결은 6단계 AG-02·AG-06) |

- A·B는 사람에게 묻지 않는다. A는 그대로 청사진에 반영하고, B는 AI가 확인을 마친 뒤 결과에 따라 A·C·D로 다시 분류한다.

### RQ-05 · 물을 것만 묻고, 물을 때는 선택지로 한다 (전 단계 공통) **[사람 확인]**

- 묻기 전에 답이 이미 정해져 있는지 본다. 규칙·문서·기존 코드로 답이 하나로 정해지면 묻지 않고 적용한 뒤 보고에 적는다.
  - 예: 워크트리 위치(12단계 WT-05), 브랜치명(7단계 BR-01), 커밋 scope(7단계 BR-03), `@author` 값과 못 찾은 프로그램ID의 `NA`(CLAUDE.md).
- 사람에게 묻는 것은 근거가 없거나 근거끼리 갈려서, 고르는 안에 따라 결과가 달라지는 경우(2단계 RL-01~05)뿐이다. developer 세션은 선택지를 qa-master에게 제시하고, 사람에게는 qa-master가 묻는다(2단계 RL-12).
- 사람에게 결정을 요구할 때는 선택지(후보안) 형태로 제시한다.
- "라벨 문구를 뭐라고 할까요?" 같은 서술형 개방 질문을 그대로 던지지 않는다. AI가 후보안을 2개 이상 만들어 제시하고, 사람은 그중 고르거나 직접 입력(기타)한다.
- 진짜 자유 서술이 필요한 경우에도 "예시안 n개 + 직접 입력" 형태로 바꿔 제시한다.
- 제안·권장을 요청받으면 선택지 나열로 끝내지 않고 권장안 1개와 이유를 분명히 밝힌다. 권장하지 않는 안은 "비권장"으로 명시하고 이유를 쓴다. 새 조건이 오면 입장을 바꾸되 무엇이 바뀌어서 바꿨는지 밝힌다.
- 가능하면 `AskUserQuestion` 도구를 쓴다. 쓸 수 없으면(텍스트 전용 보고, 완료 보고서 등) 아래 템플릿을 따른다.

```
[질문] (한 줄 요약)

배경: (왜 결정이 필요한지)

영향: (이 결정이 막고 있는 작업 — 세션·건수. 없으면 생략)

선택지:
A. (옵션 설명) — 영향/트레이드오프
B. (옵션 설명) — 영향/트레이드오프

권장: A/B 중 하나 + 근거 한 줄 (비권장안이 있으면 "비권장"으로 명시하고 이유)
```

이 형식은 이 단계의 초기 질문뿐 아니라 사람에게 결정을 요구하는 모든 순간에 같게 적용한다. 예:

| 상황 | 정본 |
|---|---|
| 구현 중 새 불확실성 발견 | 4단계 GT-03 |
| Agent 간 소통 결과 보고, 담당 세션 연결 승인(qa-master는 상시·대리 승인) | 6단계 AG-02, AG-08 |
| 공통코드 후보 제시 | 9단계 CC-04 |
| 대상 화면·경로 정정이 모호할 때, E2E 계정이 없을 때 | 10단계 TS-08, TS-11 |
| 기본 포트를 다른 세션이 아직 사용 중일 때 대기 여부(예/아니오) | 12단계 WT-10 |


### RQ-06 · 사람의 답변을 받으면

AI가 예를 들어 "CTRT_AMT와 CT_CTR_BSC 중 어떤 값을 총 계약금액으로 사용할지 확인 필요"라고 물었을 때, 사람은 다음 중 하나로 답한다.

- 알고 있으면 바로 답한다.
- 모르면 "테이블명세서의 X 섹션을 확인해라"처럼 확인할 곳을 알려준다.
- 기획 확인이 필요하면 "기획 확인 필요"라고 답한다. 이때 AI는 결정사항과 배경, 고려한 선택지를 문서화한다. RL-12 위임 범위의 기획 확인은 qa-master가 근거를 기록해 확정할 수 있다.

### RQ-07 · 청사진 양식

사람의 답변을 받은 AI는 다음 항목으로 청사진을 최종 정리한다.

| 항목 | 내용 |
|---|---|
| 화면 | 어떤 데이터가 표시되는가, CASE별로 화면이 어떻게 달라지는가, 입력/선택값은 무엇인가 |
| 데이터 | 어떤 테이블·컬럼을 쓰는가(테이블 명세 기준 물리명·타입, 명세와 DB·코드의 차이 포함), Query는 어떻게 구성되는가 |
| API | 기존 API 재사용 여부, 신규 API 필요 여부, BFF 필요 여부, Feign 필요 여부 |
| 프로젝트 변경 범위 | 아래 예처럼 프로젝트별로 정리 |
| 결정사항 | 사람이 결정한 내용 |
| 미확정사항 | 구현 전에 반드시 확인해야 하는 것만 남긴다 |

- API 항목: 외부 API가 필요한 검색 조건을 지원하지 않을 때 BFF에서 여러 번 호출해 합집합으로 맞추는 방식은 후보안에 올리지 않는다(서버 페이징·총건수·정렬·중복 제거가 부정확해진다). 대안은 화면 옵션 조정(기획 확인), 상대 프로젝트에 지원 요청(사람 또는 qa-master 지시), 기획 확인 후 결정이다.

```
buy
 └─ 화면 + BFF
contract
 └─ API 수정
sell
 └─ 변경 없음
```

### RQ-08 · 설정·코드의 주석보다 실제 값을 우선한다

설정 파일이나 코드의 주석, 문서 서술을 근거로 인용하기 전에 실제 값(설정의 실제 키·기본값, 코드 자체)과 대조한다. 주석은 낡아 실제 동작과 다를 수 있다.

> 실제 사례(2026-10-28): buy `application.yaml` 주석은 "member host는 contract의 DummyMemberController 임시 사용"이라고 적혀 있었으나 바로 아래 실제 기본값은 member 서버 포트(`${EXTERNAL_MEMBER_HOST:http://localhost:8084}`)였다. 낡은 주석이 청사진 서술·qa-master 판단에 그대로 들어갔다가 사용자 지적으로 정정됐다.
