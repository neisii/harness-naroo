# 09 — coordinator (작업 쪼개기·나눠주기)

> **핵심 한 줄:** blueprint를 독립 단위로 **쪼개** 유휴 에이전트에 **나눠주고** 결과를 게이트로 넘기는 엔진.
> 멀티에이전트 생산성의 "빠진 조각" 중 02 고유로 남은 것(backlog T3 승격).
> 단, **쪼개기는 기반 정보가 명확할 때만** 안전하다(문서 02 #3).

---

## 역할 (무엇을 하나)

blueprint → ① **독립 단위로 쪼개기** → ② **유휴 에이전트에 나눠주기** → ③ 결과 수집 → ④ 게이트로 넘김.
(합치기=뒷단 05, 검증=게이트. coordinator는 **앞단만**.)

> 쉬운 예로, 큰 주문서(blueprint)를 받아 **일감으로 쪼개** 노는 알바생에게 **나눠주는 반장**이다.
> 요리(합치기)·검수(게이트)는 다른 사람 몫.

## 전제조건 — 쪼갤 수 있을 때만

기반 정보·요구사항이 **명확한 영역만** 쪼개 병렬화한다(02 #3). 모호하면 쪼개기 금지 →
**사람 게이트(명확화 먼저)**. coordinator의 첫 판정은 **"이 blueprint를 깨끗이 쪼갤 수 있는가?"**

## 좋은 단위의 조건 (쪼개기 정책)

- **독립성:** 단위끼리 같은 파일·공유 로직을 안 건드림. 건드리면 그 부분을 먼저 직렬화(→ T4 의존성).
- **검증가능:** 각 단위가 **홀로 verify 게이트를 통과**할 수 있음.
- **적정 크기:** 너무 크면 병렬 이득이 없고, 너무 작으면 나눠주는 비용이 더 든다.

## 나눠주기 = 풀 큐 + 작업 락

- **풀(pull):** 유휴 에이전트가 **스스로** 다음 단위를 집어간다(밀어넣기 아님) — 반장이 일일이 안 먹여도 돌아감.
- **락:** 한 단위는 **한 에이전트만**. 중복 작업 방지.
- AG-15 "대기 추적" 장부를 **"할 일 큐"**로 확장(상태: 대기/진행/완료/막힘).

## 의존성 (→ T4 DAG)

평면 큐가 아니라 **"A 끝나야 B"** 선후. **공유 로직 변경은 먼저**(05 얽힘의 극단 사례 — 먼저 떼어 배포).
coordinator는 DAG를 보고 순서대로 푼다.

## 구현 선택 — 직접 vs 실행층 (추천)

- Claude Code의 **Agent/Workflow를 실행층(근육)**으로 쓰고, coordinator는 **그 위의 규칙**
  (쪼개기 정책·락·게이트 라우팅)만 쥔다. → 근육(병렬 실행·수집)을 재발명하지 않고, value-add는 규칙(02).
- **직접 구현**은 스케줄러·수집을 다시 짜야 함 — 비권장.

> 비유하자면, 반장은 **작업장(Workflow)을 새로 짓지 않고**, 거기서 "누가·뭘·순서·겹침 없이" 하는 **규칙**만 쥔다.

## operating loop에서의 위치

blueprint → **[coordinator: 쪼개기·나눠주기]** → feature 격리 → 병렬 실행 → 게이트… (문서 00 작동 루프의 SPLIT 노드.)

## 하네스 규칙과의 결합

coordinator는 **나눠주기만** 한다:
- 각 단위의 "완료"가 진짜인지 → **게이트(verify·정직성·경계, 02 POST)**
- 혼자 할지 물어볼지 → **가역성 분류표(07)**
- 합치기·릴리스 → **05**

경계가 깨끗해야 coordinator가 단순해진다.

## 못 하는 것 (정직하게)

- **모호한 blueprint는 못 쪼갠다** → "쪼갤 수 없음"을 보고하고 사람 게이트로. (억지로 쪼개면 02 #3대로
  N개 에이전트가 같은 모호함을 N번 잘못 넘겨짚는다.)
- 의존성 해소(T4)·얽힘(05)은 coordinator 밖 — 참조만.

## 확정된 설계

- **할 일 큐 = AG-15 장부 확장(03과 공유).** 단위 하나 = `{단위id · 상태(대기|진행|완료|막힘|parked) · 락(에이전트id 또는 없음) · 의존[](선행 단위id) · 결과포인터}`. coordinator의 큐는 **03의 대기·parked 장부를 확장한 것** — 새 저장소를 만들지 않는다.
- **락 = 장부 기반 단일 소유.** 한 단위는 한 에이전트. 유휴 에이전트가 pull할 때 장부에 락(에이전트id)을 먼저 쓴다 → 경합은 **먼저 쓴 쪽이 소유**(compare-and-set). 파일 락을 따로 두지 않고 장부로 일원화(이미 AG-15가 있으므로 단순).
- **Workflow 연동 = 실행층은 Workflow, 규칙은 coordinator.** PRE(coordinator): 쪼개기 정책·락·의존 순서. 실행·병렬·수집: Workflow(근육). POST: 결과를 게이트로 넘김(02). coordinator는 Workflow를 **호출**하되 "누가·뭘·순서·겹침 없이"의 **규칙만** 쥔다.
- **실패·재시도 = 격리 후 재투입, 그 뒤 parked.** 단위 실패 시 **그 단위만** 격리(나머지는 계속), 기본 2회까지 재투입, 계속 실패하면 `막힘`/`parked`로 내려 **03의 제쳐-당김과 같은 처리**(사람에게 사전소화해 올림).
- **우선순위 = 03 다음(이제 열림).** "사람 검수가 병목이면 나눠주기 자동화 효용이 제한된다"는 전제는 유지. 03이 정본화됐으니 **이제 coordinator 차례**다.

## 남은 운영 선택 (쓰면서 정함)

- 재시도 횟수(기본 2)·적정 단위 크기 임계.
- 장부 compare-and-set의 구체 구현(원자적 쓰기 방식). 스킬화는 07·03과 같은 규칙 — **실제로 한 번 돌아 굳은 뒤.**
