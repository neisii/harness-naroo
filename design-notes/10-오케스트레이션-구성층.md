# 10 · 오케스트레이션 구성 층 (0.2.0)

> **버전 로드맵에서의 자리:** `0.1.x` = per-세션 규율 층(독립 사용). **`0.2.0` = 이 문서가 설계하는 오케스트레이션 구성 층**(여러 세션을 엮어 돌릴 때만 켜는 opt-in). backlog [T8]의 정본 설계.
> **전제(바꾸지 않음):** per-세션 규율(청사진→승인→구현→검증·가역성·커밋안전·서술)은 그대로 둔다. 이 층은 그 위에 **얹는** 것이지 규칙을 고치는 게 아니다.
> **상태:** D-1~D-4 처분 완료 · 최소 모드 **개밥 1회 검증 통과**(부록 B·C, 2026-11-16) · **② 좁은 위임 설계 완료**(D-2, 2026-11-17, 위임 경계 = 07을 게이트에 적용). 남은 건 ②의 개밥 검증 + 그 외 미검증(유휴 한계·coordinator·스케일).

---

## 1. 왜 필요한가 — 개밥이 드러낸 이음새

0.1.2 개밥(`status-relay-rebuild`, 2026-11-15)에서 선이 깨끗하게 갈렸다.

- **per-세션 규율은 빈 저장소에서 혼자 잘 돌았다.** 청사진·가역성·커밋안전·서술 모두.
- **터진 건 전부 "여러 세션을 엮는 구성"이었다.** 오케스트레이터 세션이 하위 세션 둘을 띄우려다, 사람+세션이 문답으로 **하나씩 짜 맞춰야** 했다(위임기록.md까지 수기 작성).

세션 자신이 남긴 한 줄이 정곡이다: **"이름만 qa-master일 뿐 규칙의 절반이 안 돈다."** 하네스 규칙이 **qa-master·대기 장부(AG-15)·순찰·공유문서 루트가 이미 있다고 전제**하는데, 새 저장소엔 그게 딸려 오지 않는다.

→ 이건 범용화에서 계속 본 문제(규칙이 환경 전제를 강요)가 **오케스트레이션 층에서 똑같이 터진 것**이다. 06(핵심+환경값)의 "환경값 가이드" 패턴을 여기에 적용한다.

## 2. 설계 원칙

- **opt-in·비파괴.** 이 층을 안 켜면 1단계(per-세션)가 그대로 혼자 돈다. 켜야 여러 세션 오케스트레이션이 열린다.
- **선언하고 가리킨다, 강요하지 않는다.** 규칙은 역할만 말하고(결정자/검수자/구현자), 구체 인프라는 **"있다/없다(면제)"를 선언**하게 한다. 06 그릇과 같은 결.
- **바닥만 깔고 결정은 드러낸다(가드레일).** 자동 구성은 **인프라를 세팅하고 결정 지점을 사람에게 보여주는 데까지만.** 위임을 자동 부여하거나 게이트를 대신 승인하지 않는다 — 개밥에서 세션이 **자기 청사진 자기 승인을 거부**하고 **"전달된 승인은 승인이 아니다(RL-12)"**를 지킨 건 하네스가 선을 지킨 것이지 버그가 아니다. 그 선을 자동화로 허물면 하네스의 존재 이유가 무너진다.

## 3. 최소/소규모 모드 — 이 층의 심장

**목표(최소 모드의 그림, 사용자 확정 2026-11-15):** `사람(결정) → 게이트웨이 세션(전달·감시) → 실무자 세션(구현)` **3층 관계를 세우는 것.** 핵심 단서 하나 — **게이트웨이 세션은 결정하지 않는다.** 사람의 승인을 원문 그대로 실무자에게 전달하고 상태를 감시할 뿐, 스스로 게이트를 승인하지 않는다(승인=게이트는 끝까지 사람). "게이트웨이"는 **관문이 아니라 통신·감시 창구**로 읽는다. 최소 모드는 이 관계만 세우고, 아래 전제 인프라는 사람이 대신 메운다.

하네스 규칙이 전제하는 오케스트레이션 인프라를, 소비 저장소가 **갖췄는지 선언하거나 명시적으로 면제**하게 한다. 전부 갖춘 "완전형"(원본 SI)과, 아무것도 없는 "소규모"(개밥 저장소) 사이를 한 설정으로 잇는다.

| 전제 인프라 | 완전형(원본) | 소규모 모드(면제 시 대체) |
|---|---|---|
| 결정 권한자(qa-master) | 전용 세션 + 위임 범위 | **사람이 직접 모든 게이트 승인**(오케스트레이터는 전달만) |
| 대기 장부(AG-15) | `<공유문서 루트>\지시대기\대기현황` JSON | 장부 생략, 또는 단일 파일 간이 장부 |
| 순찰(patrol) | 전용 세션 + `/loop` 알림 | 생략(사람이 직접 상태 확인) |
| 공유문서 루트 | 세션 공유 폴더 | 저장소 내 단일 폴더 또는 생략 |
| 문의처(AG-16 ③) | qa-master | **사람(또는 지시한 세션)에게 직접** |

→ "소규모 모드 = 장부·순찰·qa-master 없이, **사람이 결정 창구이고 오케스트레이터는 전달·감시만**." 개밥에서 사람이 손으로 고른 바로 그 구성(B안: 범위를 좁힌 위임)이 이 모드의 첫 사례다.

## 4. 설정 결정 체크리스트 (자동 구성 후보)

개밥에서 **하나씩 짜 맞춘** 결정들. 자동 구성 층이 이걸 **세팅하고 결정 지점만 사람에게 묻는다.**

1. **오케스트레이터 정체성·위임 범위 선언·기록.** 누가 오케스트레이터인가, 무엇을 위임받았나. 개밥의 `위임기록.md`를 정식 포맷으로.
2. **전제 인프라: 갖춤 / 면제 선언.** 장부 위치(AG-15)·문의처(AG-16③)·공유문서 루트·순찰 — 각각 "있음(경로)" 또는 "면제(대체 방식)".
3. **역할 분리.** 오케스트레이터 ≠ 구현자(자기 승인 방지). 구현은 별도 developer 세션으로.
4. **세션 생성 레시피.** 모델·권한 모드·AG-16 3줄 지시문·세션 이름(중복 회피).
5. **자식→오케스트레이터 깨움.** 하위 세션이 게이트에서 보낸 메시지가 유휴 오케스트레이터를 깨우는가(개밥 "미확인").

## 5. 열린 결정 (아키텍트가 먼저 정해야 — 이게 정해져야 sub 할당 가능)

각 항목에 **후보 + 내 권고**를 단다. 사용자 확정 전까지는 전부 잠정.

### D-1. 최소 모드의 구체 — 뭘 켜고 뭘 끄나  **[확정 2026-11-15: 후보 A]**
- **후보 A(확정):** 장부·순찰·qa-master 전부 면제(=0.2.0 첫 걸음 스코프 밖, 그 역할은 사람이 메움), **사람이 유일 결정 창구**. 게이트웨이 세션은 전달·감시만. = 개밥 B안 그대로. §3 "목표"의 3층 관계가 이것. 가장 단순·안전.
- **재조정(2026-11-17, D-2 ② 설계 반영):** "게이트웨이는 결정 안 함"은 **② whitelist가 빈 경우(순수 최소 모드)**의 모습이다. ②를 켜면 → **"게이트웨이는 위임기록의 07-자율 게이트만, 검증(독립+새맥락) 통과 시 결정; 나머지 전부 에스컬레이션."** 최소 모드는 그 특수 케이스로 자연 포함된다.
- 후보 B: 단일 파일 간이 장부만 켜서 "누가 뭘 기다리는지"는 남기고 순찰은 생략.
- **권고 근거:** 첫 걸음은 "되는 최소"가 맞다. 장부·순찰은 세션 수가 늘 때 가치가 생기므로 뒤로.

### D-2. 위임 기록 — ① 목록화(2026-11-15) · ② 좁은 위임 설계(2026-11-17)  **[설계 완료]**
- **① 목록화(최소 모드):** 사람이 게이트웨이에 위임한 것을 글로 남긴다. 최소 모드에선 위임 대상 = **코디네이션 역할만**(실무자 세션 생성·사람 승인 원문 전달·상태 감시), 게이트 결정은 비위임. 포맷: 저장소 내 `위임기록.md`(부록 A). 이것만으로 3층 관계는 섬(= 아래 ② whitelist가 빈 특수 케이스).
- **② 좁은 위임 — 위임 경계 = 07(가역성 분류표)을 게이트에 적용:** 게이트웨이가 **일부 게이트는 사람 대신 승인**해 사람 부담을 던다. 어떤 게이트를 위임할지는 임의 목록이 아니라 **07을 게이트에 돌린 결과**다.
  - **위임 가능**(게이트웨이가 검증 통과 시 승인) = 07 '자율': **가역 · 규칙 검증 가능 · 사업 결정 아님 · 범위 안.**
  - **사람 유지**(에스컬레이션) = 07 거부권: **비가역 · 모호 · 사업 결정 · 바깥으로 나감.**

| 게이트 | 위임 | 07 근거 |
|---|---|---|
| 커밋 계획 승인(CS-01) | 가능 | 가역(push 전)·규칙 검증(CS-09 제외목록·CM-11 서명) |
| 요구사항·결과 대조(CM-01) | 가능 | 규칙 검증(청사진↔코드·테스트) |
| 청사진 승인(GT-02) | 사람 | 설계 판단·모호(거부권) |
| push · PR · 머지 | 사람 | 비가역·바깥으로 나감(거부권) |
| 되돌리기 어려운 git(CS-06) | 사람 | 비가역(거부권) |
| 사업 결정(할인율 등) | 사람 | 사람이 정할 일(거부권) |

  - **검증은 안 건너뛴다(자기 채점 방지의 핵심):** 위임 게이트도 **독립 검증 + 새 맥락 재검증을 통과해야만** 게이트웨이가 승인한다. 위임은 "누가 '승인'이라 말하나"만 사람→게이트웨이로 옮길 뿐, **검증 규율(2026-11-16 개밥에서 실증)은 그대로.** 게이트웨이 ≠ 실무자라 자기 일을 자기가 승인하는 일은 없다.
  - **기록·번복(RL-12):** 게이트웨이의 모든 승인을 결정기록에 **근거째(검증 결과 포함)** 남긴다. 사람은 그 승인도, 위임 자체도 **언제든 번복**. 위임 범위 내 승인은 "사람이 한 것으로 인정"하되 기록으로 감사·가역이 보장된다.
- 포맷: `위임기록.md`(md) — 사람이 읽고 번복하기 쉬움. ② 켜면 "위임한 게이트" 절(위 분류)을 더한다.
- **미검증:** ② 자체는 아직 개밥 안 함(최소 모드만 2026-11-16 검증). 다음 개밥 = 위임 게이트에서 게이트웨이가 검증 통과 후 **자율 승인**하는 걸 실제로 돌려보기.

### D-3. coordinator(작업 나눠주는 엔진) — 큐·락·Workflow 연동  **[확정 2026-11-15: 첫 걸음 제외]**
- 이건 [09 coordinator](./09-coordinator.md)·backlog T3의 소관. 이 층의 **한 부품**이되, 최소 모드엔 불필요(사람이 작업을 나눔).
- **확정:** 0.2.0 첫 걸음에서 **제외.** coordinator는 세션 수·작업량이 커질 때 붙인다. 최소 모드(사람이 작업 나눔)를 먼저 검증.

### D-4. 자식 메시지 깨움 메커니즘  **[관측 확정 2026-11-16: 후보 B — 깨어남]**
- **확정 기본(후보 B):** 자식은 **게이트에서만 보내고 멈춰 대기**, 게이트웨이는 **수신 시 스스로 깨어난다.** 폴링(후보 A)은 불필요.
- **근거(실측):** 개밥(status-relay-rebuild, 2026-11-16)에서 **idle 게이트웨이가 두 실무자의 SendMessage를 받아 자율로 깨어나 사용자에게 중계**하는 것을 관측함(사용자 확인). 이전 "경험 근거" → **실측으로 승격.**
- **아직 미검증:** 유휴 정리 한계("60분")는 이번 개밥에서 안 봤다 — 여전히 **약속값**(실존·값 미확인). 긴 유휴는 다음에. `/exit`는 종료.

### D-5. 워커 세션 루트 전략  **[권고 확정 2026-11-18, 실전 A/B 검증 대기]**
워커 세션을 본 폴더에서 띄우나, 워크트리에서 띄우나. 권한 프롬프트 반복의 뿌리.
(본 폴더 = 워크트리 말고 프로젝트 최상위 체크아웃. 워크트리는 그 밑 `.claude/worktrees/<이름>`.)

**빠져 있던 설정(근본 원인):** `worktree.bgIsolation` = 백그라운드 세션이 본 폴더를 직접 고쳐도 되는지 정하는 Claude Code 설정(스키마 실존 확인, 2026-11-18).
- 기본값(`worktree`): bg 세션의 본 폴더 쓰기 차단. 워크트리에 들어가야만 씀.
- `none`: bg 세션이 본 폴더를 직접 고침.

하네스 규칙(12단계)은 `none`을 전제로 쓰였으나 실제로 어디에도 설정 안 됨 → 기본값으로 작동. **설정 구멍**(규칙이 전제만 하고 설치·검증 안 함 — 부록 B "프로젝트 밖"과 같은 계열). 그 기본값 결과가 아래 둘.
- 작업 5에서 워크트리 자동 생성.
- 청사진이 본 폴더에 안 써지고 임시 폴더에 갇힘.

**루트 선택(`none` 깐 상태):**
- 옵션 A(워크트리 루트): 쓰기 OK, 단 문서 읽기 때 "본 폴더 밖"이라 또 프롬프트.
- 옵션 B(본 폴더 루트): 읽기·쓰기 다 프롬프트 없음. 단 git은 `git -C <워크트리>`로 지정(bare `git`=main 위험, 커밋 전 검사가 보조).

**권고:** 옵션 B. 마찰 최소 + 게이트웨이("본 폴더 루트 + `git -C`")와 루트 전략 통일.
**대가:** `none`은 본 폴더 쓰기 가드를 끔 → 안전망은 워커 규율 + 커밋 전 검사만. 설정은 전역 말고 해당 프로젝트에만 적용(전역 `none`은 하네스 안 쓰는 레포까지 가드 해제).
**미검증:** 실전에서 B를 돌려 A/B 비교(다음 개밥).

## 6. 하지 않는 것 (non-goals)

- per-세션 규율(1단계)을 바꾸지 않는다.
- 위임을 자동 부여하지 않는다(사람의 명시적 지시만 근거).

## 부록 A. `위임기록.md` 템플릿 (초안, D-2 ① 산출물)

D-1·D-2 확정에 맞춘 **최소 모드** 버전. 게이트웨이에 위임하는 것은 **코디네이션 역할뿐이고 게이트 결정 권한은 위임하지 않는다**는 점을 글로 고정한다. 저장소 안에 두고, 사람이 언제든 번복한다.

```markdown
# 위임 기록 (orchestration)

- 저장소:
- 오케스트레이터(게이트웨이) 세션:
- 실무자(developer) 세션:
- 기록 시작: YYYY-MM-DD
- 모드: 최소(소규모) — 장부·순찰·qa-master 면제, **사람이 유일 결정 창구**

## 사람이 게이트웨이에 위임한 것 (코디네이션 역할만)
- [ ] 실무자 세션 생성·종료 (모델·권한 모드·AG-16 3줄 지시문)
- [ ] 사람의 승인을 **원문 그대로** 실무자에 전달
- [ ] 실무자 상태·진행 감시, 막히면 사람에게 보고

## 위임하지 않은 것 (= 사람이 직접 결정)
- 모든 게이트 승인: 청사진 승인(GT-02), 커밋 계획 승인(CS-01),
  요구사항·결과 대조(CM-01), push, 머지
- 되돌리기 어려운 git(CS-06), docs 커밋 등 [사람 확인] 지점 전부

## 근거·번복
- 근거: 사용자 지시 "<원문>" (일시)
- 상태: 유효 / 번복됨(<일시·사유>)
- 사람은 언제든 이 위임을 거둬들일 수 있다. 게이트웨이는 위 "위임한 것"
  밖의 모든 결정을 사람에게 올린다(화이트리스트: 목록에 없으면 에스컬레이션).
```

> 이 템플릿은 **최소 모드(① 목록화)**다 — 게이트 결정 위임을 담지 않는다. **② 좁은 위임을 켜면**(D-2, 2026-11-17 설계), 아래에 **"위임한 게이트" 절**을 더한다: 07-자율 게이트(CS-01·CM-01 등)를 "게이트웨이가 검증 통과 시 승인", 거부권 게이트(GT-02·push·머지 등)는 "사람". 게이트웨이의 승인은 §3 결정 기록에 근거째 남겨 사람이 번복할 수 있게 한다(RL-12).

## 부록 B. 개밥 1차 소견 (2026-11-16, status-relay-rebuild)

최소 모드를 실제로 돌려(게이트웨이 1 + 실무자 2) 얻은 1차 관측.

**통한 것:**
- **깨어남(D-4):** idle 게이트웨이가 실무자의 SendMessage로 **자율 깨어남** → 관측 확정.
- **3층 중계:** 실무자가 게이트에서 멈춰 **파일 0 변경**, 게이트웨이가 **승인 안 하고 중계만**, 사용자가 결정 — 설계대로.
- **가드레일:** 게이트웨이가 분류기(`[Undermining Oversight]`)에 막히자 **우회 안 함** → RL-12 선이 실전에서 지켜짐.
- **가드레일 2(미세·강력):** 사용자의 "승인"이 **터미널 입력 버그로 "승"으로 잘려** 전달되자, 게이트웨이가 **승인으로 해석하길 거부**하고 정확한 문구를 다시 요구함 — 잘린/비표준 신호를 승인으로 **세탁하지 않음**. 엄격함이 **깨진 입력이 승인으로 통과하는 것까지 막아줌**(사람 권한 보호). 또 작업 1의 **"A"를 경로 결정으로만** 전달하고 **구현 승인과 분리**함(한 메시지 ≠ 모든 게이트).
- **독립 검증(강력):** 작업 1 구현 완료 후 게이트웨이가 **세션 자기보고를 그대로 믿지 않고 워크트리에서 직접 확인** — 스테이징 2파일(`docs/`·`wrangler.toml` 없음 확인), 코드를 청사진과 대조, `gofmt`·`go vet`·`go test -race` 재실행 → **검증된 커밋 계획을 사용자에게 올림**(승인은 여전히 사람). "검증은 검증으로만·자기보고 불신" 규율이 중계 층에서 작동. 게이트웨이의 '감시'가 '독립 재확인 후 전달'로 자연 확장됨(결정은 안 함).
- **★ 재검증(새 컨텍스트)이 게이트웨이가 놓친 걸 잡음 — 하네스의 존재 이유가 증명됨:** 게이트웨이의 (같은 맥락) 자체 검증은 **전부 PASS**였는데, **새 컨텍스트 subagent 검증자**가 ① 완료보고서 CM-02 항목 제목 누락(경미) ② 커밋 **scope 차이**(CS-08: `fix(engine)` vs 프로젝트 기존 scope) ③ 메시지 초안이 보고서에 없어 **판정 불가** 를 잡아냄. **같은 맥락 검증자는 맹점이 있고 새 맥락이 더 잡는다**가 실증됨. = "개별 성공이 아니라 **전체 정합성을 독립적으로 확인**"이라는 하네스 핵심 명제(첫 고객 한 방)가 개밥에서 증명됨. 게이트웨이는 FAIL을 근거째 사용자에게 올리고 **승인 전달을 보류**함(커밋 전 자기 채점 방지). 또: 커밋 전 재검증은 승인 원문 전달을 **막아 세우는 실제 게이트**로 작동.
- **재검증이 또 잡음(작업 5):** 두 번째 작업의 재검증도 완료보고서의 **사실 오류 2건**(메서드명 `Proxy`→`Router.SetMetrics`, `p99` 필드 누락)을 잡아 실무자가 수정. **두 작업 모두에서** 독립 재검증이 실제 부정확을 잡음 — 한 건이 아니라 두 건.

## 부록 C. 개밥 1차 결론 (2026-11-16)

최소 모드가 **전 구간**을 안 깨지고 돌았다: 세션 생성 → 게이트 왕복 → 구현 → 게이트웨이 독립검증 → 사용자 승인 → 새 맥락 재검증 → 수정 → `amend` → 재검증 통과 → push 대기. D-4 깨움 **관측 확정**, 3층·가드레일·게이트웨이 독립검증·새 맥락 재검증이 전부 실전에서 섰고, **재검증이 두 작업 모두에서 진짜 구멍을 잡아**(CM-02·scope / 사실오류 2건) 하네스 핵심 명제("전체 정합성을 독립적으로 확인")를 증명했다. → **최소 모드 설계 검증 1회 통과.**

미검증으로 남긴 것(다음 개밥·단계): 유휴 한계("60분")의 실존·값 · coordinator 큐·락(D-3 제외) · 장기·다세션 스케일 · 워커 루트 전략(D-5). **② 좁은 위임은 설계+개밥 검증 완료(부록 D, 2026-11-17).** 세팅 마찰 2건(규칙 읽기 권한·산출물 저장 경로)은 가이드에 반영됨.

## 부록 D. ② 좁은 위임 개밥 결과 (2026-11-17, status-relay-rebuild / main-tests)

② 좁은 위임(CS-01·CM-01을 게이트웨이가 자율 승인)을 실제로 돌려 **검증 통과.**

**핵심 — CS-01 자율 승인이 작동:**
- 워커가 커밋 계획(CS-01)을 보내자 게이트웨이가 **사용자에게 안 올리고** 독립 검증 + 새 맥락 재검증을 거쳐 **스스로 승인**(RL-12 귀속: 사용자 번복 가능, 결정기록에 근거째). = ②의 목적(사람 승인 부담 ↓) 실현. 비위임 게이트(push·PR)는 **여전히 사용자에게 에스컬레이션.**

**★ 위임해도 검증 바가 안 낮아짐 — 오히려 정직을 강제함:**
- 워커 커밋 메시지가 **"동작 그대로"**라고 적어 **실제 동작 차이**(바인드 실패 시 기동 로그 2줄 사라짐)를 숨김. 게이트웨이(+새 맥락 검증자)가 **잡아내** 메시지를 그 차이를 명시하도록 고치고(CM-08 하이픈 목록)·완료보고서 보정 지시 후에야 승인. 검증자는 워커가 "미검증"이라던 SIGTERM까지 직접 확인(exit 0).
- = **"위임 = 승인 주체만 사람→게이트웨이, 검증 규율은 그대로"**가 실증. 게이트웨이가 권한이 있다고 바를 낮추긴커녕 **워커의 어물쩍을 걸러 더 정직하게** 만듦 — 하네스 핵심 명제가 위임 상황에서도 성립.

**★ 1회 지시 ≠ 상시 위임 — scope creep 없음 (2026-11-18 후속 관측):**
- 사용자가 PR·병합(**BR-06** = 07-거부권, 비가역·바깥으로 나감)을 **그 한 번만** 게이트웨이에 넘김("네가 두 브랜치 pr 및 병합해"). 게이트웨이는 실행하되 **안전 사전확인**(두 PR MERGEABLE/CLEAN·GitGuardian pass·PR 본문 AI 서명 없음) 통과 후, 기록에 **"이 건에 한해 위임 범위 밖 게이트를 사용자가 직접 지시"**로 남기고 **"앞으로 push·병합은 원래대로 사람 몫"**이라 명시함 — **②로 확대하지 않음.**
- = 게이트웨이가 게이트를 넘는 길은 **둘.** **상시 위임(② 화이트리스트 = 지속·검증 후 자율)** vs **1회 지시(그때만 실행, 게이트는 그대로 사람).** 둘 다 "사람이 범위를 정함"이되, **1회 넘김이 상시 권한으로 새지 않는다**를 실전 확인 — 볼륨 다이얼 모델의 **안전성(scope creep 없음)** 검증.

**결론:** ② 설계 검증 통과. **사람은 덜 귀찮되 정합성은 안 깎임(오히려 올라감).** D-2 ②·D-1 재조정이 실전에서 검증됐다.
- **위임기록 적응:** 위임기록이 최소 모드로 바뀐 걸 게이트웨이가 알아채고 CS-01·CM-01을 전부 사용자 승인으로 재조정 → 전사 패턴 정상.

**미해결 세팅 구멍(→ 가이드 반영):**
- **규칙 읽기 권한:** bg 실무자는 `acceptEdits`여도 **프로젝트 밖 규칙 폴더**(플러그인 캐시)를 못 읽어 권한 프롬프트에 멈춤. 게이트웨이는 못 풀어줌(권한=사용자). → **좁게 미리 허용**(attach 1회 / `settings.json` allowlist).

둘 다 **권한·격리가 "프로젝트 밖"에서 생기는 마찰** — 세션 생성 레시피에 "밖을 미리 열어둔다" 한 줄이 빠졌던 것.
