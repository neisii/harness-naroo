# 일반화 대상 — 공개 rules/의 환경 구조 가정

> 목적: 공개 `rules/`(구체본, S 차세대 SI)에 스며든 **환경 구조 가정**을 찾아, 06(두 하네스: 핵심 + 환경값) 틀로 **핵심 원리**와 **갈아끼우는 환경값**으로 분리하기 위한 작업 인벤토리.
> 배경: 타인이 이 하네스를 쓸 때 `{본인 경로}\IdeaProjects\project_docs` 같은 전제가 **강제처럼** 느껴진다는 지적(2026-11-14). 전제를 강요하지 않고 예시·설정값으로 바꾼다.

## 분류 원칙 (06)

- **핵심:** 환경이 바뀌어도 안 바뀌는 원리(사람 게이트·검증=검증·비동기 검수·가역성·청사진→승인→구현→검증 흐름).
- **환경값:** 조직·스택·OS·폴더에 따라 갈아끼우는 것(경로·빌드 명령·역할 이름·보안도구·헤더·브랜치 스킴).
- 규칙은 **역할만** 말하고, 구체 값은 **설정/예시**로 뺀다. 구체값은 지우지 말고 "예시"로 남겨 진정성을 지킨다.

## 대상 (범주별)

### A. 경로·워크스페이스 구조 — 난이도 중, 상태: 대부분 완료(2026-11-14)
- 전제: `{본인 경로}\IdeaProjects\project_docs`, 산출물 `docs\<팀구분>\<이름약자>\<작업명>`, `지시대기\대기현황`, `_작업중`, junction(`project_docs\docs\{admin…}`→`prj_*\docs`), `\\?\` 롱패스.
- 위치: 00·1·2·8·9·10·11·12.
- 방향: **전부 환경값.** "산출물 루트 / 대기 장부 위치 / 워크스페이스 루트"를 설정값으로. 규칙은 "산출물은 지정된 산출물 루트에"처럼 역할만.

### B. 브랜치·역할·팀 네이밍 — 난이도 중, 상태: 부분 완료(2026-11-14)
- 전제: 브랜치 `<팀구분>/<이름약자>_dev/<화면ID>`(BR-01), 역할 이름 `qa-master`·`scenario-master`·`*-developer`·`team2`.
- 위치: 00·7·8·10·11·12.
- 방향:
  - 브랜치 스킴 = **환경값.** 구조 `<team>/<person>/<task-id>`는 **유지**하고 플레이스홀더로 일반화 — 예: `your-teamname/ghbaek/asas-112`. 원본 `<팀구분>/<이름약자>_dev/<화면ID>`에서 **SI 특유의 `_dev` 접미사와 `<화면ID>`만 걷어낸다**(작업 id는 일반 이슈/작업 식별자). `team2`→`your-teamname`. (사람 세그먼트 자체는 유지 — 2026-11-14 확정.)
  - 역할 = **반반.** "결정자/검수자/구현자" 개념은 핵심, 이름(`qa-master` 등)은 환경값.

### C. 스택·빌드·서버·포트·메모리 — 난이도 중~상, 상태: 착수 전
- 전제: `gradlew`·`bootRun`, `ArchitectureTest`, `FeignClient`, `core 파일`, WT-10 포트, memcheck의 Java 프로세스.
- 위치: 00·1(GL-21/22)·10·11·12.
- 방향: **전부 환경값.** 핵심은 "구현 후 빌드·검증을 한다"지 "gradlew"가 아님. memcheck는 일반 프로세스로. 검증 단계가 곳곳에 퍼져 있어 손이 많이 감.

### D. 소스 헤더·사내 보안도구 — 난이도 하, 상태: 완료(2026-11-14)
- 전제: `@programId`/`@processId` 헤더, `NPROTECT`·`ANYID`(사내 보안 에이전트).
- 위치: 00·2·11·12.
- 방향: **전부 환경값/선택.** 특정 조직 전용 → 범용본은 "조직 고유 헤더·도구가 있으면 여기에" 식 조건부/예시.

### E. SI 산출물·작업 모델 가정 — 난이도 상(핵심 난제), 상태: 착수 전
- 전제: 화면설계서·공통코드·개발DB·테이블 명세·퍼블리싱·화면ID·`청사진.md`·`완료보고서.md` = "화면 단위 SI 개발" 작업 모델 자체.
- 위치: 00·2·3·8·9·10.
- 방향: **반반.** 청사진→승인→구현→검증→완료보고 흐름은 핵심. "화면설계서·공통코드·개발DB·화면ID"는 도메인 전제 → "요구명세/작업단위"로 추상화. 범용 하네스 설계의 핵심 난제.

### F. OS (Windows/PowerShell) — 난이도 하, 상태: 부분 완료(2026-11-14)
- 전제: PowerShell 예시, `Remove-Item`, `SendToRecycleBin`, `Microsoft.VisualBasic`, `\\?\`.
- 위치: 1(GL-28)·6·12.
- 방향: **환경값.** 스킬은 이미 크로스플랫폼 Python으로 포팅됨(safe-delete 등) → 규칙 문서의 PowerShell 예시만 "OS별 예시"로 중립화.

## 우선순위

쉬운 것부터 손풀기: **F · D (하) → A · B (중) → C (중상) → E (상).** E는 작업 모델 추상화라 사실상 범용 하네스 설계의 핵심.

## 진행 상태

- (완료) **D** — `@programId`/`@processId`를 "조직이 헤더 규칙을 쓰면" 조건부로. `NPROTECT`·`ANYID`를 "조직 고유 보안 토글(예: …)"로 일관화(00·2·11·12).
- (부분) **F** — GL-28(`safe-delete`로 OS 중립)·6단계(`Get-Date`→OS 중립) 완료. **12단계의 OS 특수**(`\\?\` 롱패스·`Remove-Item`·`gradlew clean`)는 Windows+gradle+경로가 한 덩어리라 **12단계 전체 일반화 때로** 미룸.
- **발견:** F·D가 "하"로 보였지만, **12단계(워크트리)에 OS·보안·경로·스택이 한 knot로 얽혀** 완전 분리가 어렵다. 12단계는 쪼개지 말고 **통째로** 일반화(실질 A·C와 함께).
- (부분) **B** — 7단계 BR-01 스킴을 `<팀구분>/<이름약자>/<작업ID>`(예 `your-teamname/ghbaek/asas-112`)로, `_dev` 제거·화면ID→작업 id. 2단계 브랜치 참조도. **단 `화면ID`는 사실상 E(화면 작업 모델)라 3·5·8·9·10·12에 깊이 퍼져 있어** B만으론 완결 불가 — 8·12의 브랜치-형식 잔존(`_dev`·화면ID)은 **E 일반화 + 12단계 knot** 때 정리. 역할 이름(qa-master 등)은 미착수.
- (대부분) **A** — ① 식별자 `화면ID`→`작업ID` 전 문서(3·5·8·9·10·12) 치환. ② **경로 루트 치환 완료**: `{본인 경로}\IdeaProjects`→`<워크스페이스>`, `…\project_docs\docs`→`<공유문서 루트>`(저장소 루트는 `<공유문서 저장소>`) — 전 문서 33+곳, 잔존 0. 플레이스홀더 뜻은 `00`에 정의. (앞서 "인라인 저가치"라던 내 판단은 틀림 — 깨끗한 기계적 치환이었다.) 남은 건 `지시대기`·`_작업중` 같은 **하위 폴더명**(공유문서 루트 내부 구조, 선택적·저우선).
- **선 긋기:** **식별자(화면ID)는 치환 완료(클린)**, **작업 모델(`화면`=화면설계서·화면 구현 등 ~80건)은 E**(미착수, 범용화의 진짜 중심). 둘은 다른 작업 — 앞서 내가 뭉뚱그려 "A가 막힌다"고 한 건 과장이었다(사용자 지적 2026-11-14).
- 나머지(A 경로루트·C·E) 착수 전. 경로루트·C·E·knot는 **환경값 매핑**(규칙은 두고 swap-list) 그릇이 더 맞음. 범용화가 어느 선에 오를 때까지 **태그 보류.**
