# 06 — 두 하네스: 핵심(불변) + 환경값(갈아끼우는 부분)

> **핵심 한 줄:** "이 프로젝트용 먼저, 그다음 범용"은 방법론적으로 정석이다 —
> 구체에서 일반을 **추출**한다(추상에서 시작하면 공허해진다). 아키텍처로는
> **핵심(어디서나 참) + 환경값(갈아끼우는 부분)**로 나눈다.

---

## 맥락

- 나는 이미 해당 SI 프로젝트에서 **철수**했다 → S 구체본은 live 운영용이 아니라
  **레퍼런스 구현 / 워크드 예제 / 포트폴리오**로서의 가치가 크다.
- 목표: ① S(폐쇄망) 기준 하네스를 **먼저** 만들고, ② 특정 환경이 아닌 **일반 업무 환경용 범용 하네스**를
  따로.

## 아키텍처: 핵심 + 환경값

| | **핵심 (불변 — 어디서나 참)** | **환경값 (환경 바인딩 — 파라미터)** |
|---|---|---|
| 합치기 | 일회용 integration + 통과분만 승격 | — (보편) |
| 검증 | 시나리오 검증 → 승격 조건 | 검증 파이프라인 구체 |
| 결정 | 릴리스 범위 게이트(go/no-go) | **배포 대상 = 폐쇄망** (일반: 프로드/앱스토어/단계배포) |
| 실적 | 내부 완료신호 ≠ 외부 인정신호 **분리** | **외부 인정 = 폐쇄망 배포** (일반: 조직별 done-done 기준) |
| 사람 | 비동기 검수(제쳐-당김, 사후감사) | 결정 위험도 분류표 |
| 격리 | 워크트리 + 작업 락 | 워크트리 경로/정책 |

## 두 인스턴스

- **S 하네스 = 핵심 + 폐쇄망 환경값.** 파라미터가 **하드코딩**된 구체 인스턴스.
  철수했으므로 **"이 방법론이 실제 폐쇄망 SI에서 이렇게 운영됐다"는 증거**로 이중 역할.
- **범용 하네스 = 핵심 + 빈 환경값 템플릿.** 환경별로 "배포 대상 / 실적 기준 / 검증 파이프"를
  **꽂아 쓰는** 형태. 지금 공개 중인 플러그인이 이쪽으로 진화하면, 설치자가 자기 환경값만 채운다.

> 비유하자면, **'어느 가게나 똑같은 뼈대'**와 **'가게마다 갈아끼우는 부분'**을 나눈다.
> 이 가게용 = 뼈대 + 폐쇄망 부분을 **끼워넣은 것**, 아무 가게용 = 뼈대 + **빈칸 틀**(새 가게는 자기 부분만 채움).

## 순서와 검증

- **순서:** S 구체본 **먼저** 완성 → "폐쇄망/실적"을 들어내고 파라미터 구멍을 뚫어 범용본 추출.
- **정합성 테스트:** "범용 규칙을 폐쇄망 환경값으로 특화하면 원래 S 규칙이 재현되는가?"
  → 재현되면 추출이 올바른 것.
- **실천 팁:** 구체본을 쓸 때 **나중에 들어낼 파라미터를 주석으로 표시**해 두면 범용본 추출이 쉬움.
  예: `<!-- PROFILE: 배포대상=폐쇄망 (범용: release-target) -->`

## 내가 정할 것

- **구체본을 어디까지 완성하고 추출로 넘어갈까?** 브랜치·검증·릴리스(04·05)만으로도 구체본의
  뼈대는 갖춰진다. 사람 병목(03)까지 넣으면 더 완전하지만 범위가 커진다.
- **범용본의 환경값을 "설정 파일"로 둘까, "역할/문서 템플릿"으로 둘까?**
  설정 파일=기계적·플러그인 친화 / 템플릿=서술적·사람이 읽고 채움.
- **공개 전략:** S 구체본은 포트폴리오로 공개(지금 레포), 범용본은 설치형 플러그인으로 공개.
  둘을 같은 레포에 둘지, 분리할지.
- **범용본의 범위:** 폐쇄망처럼 극단적 제약이 없는 보통 환경이면 "일회용 integration·비동기 검수"는
  그대로 유효하지만 "이중 실적 장부"는 조직마다 필요 없을 수도 — 환경값에서 **옵션**으로 둘지.

---

## 전체 대화의 닫는 문장

> 내 하네스의 다음 버전 = **격리 → 일회용 합치기 → 시나리오 검증 → 릴리스 결정 → 재검증 →
> 배포=main**, 그리고 사람은 이 흐름을 **비동기로 검수**(제쳐-당김 + 사후감사 + 이중 실적 장부).
> 이 전체를 **핵심+환경값**로 짜면, S 구체본과 범용본이 한 뿌리에서 나온다.
