## 새 맥락 재검증 (2026-11-21, 서브에이전트, 사용자 허락)

작성자 맥락을 물려받지 않은 검증자가 diff·청사진·WT 규칙을 읽고 임시 저장소에서 직접 시험했다. 저장소 파일은 고치지 않았다.

**1차: 조건부.** 막는 문제 1건 — `--local-base`가 이 클론의 추적 참조(`origin/<base>`)만 보고 원격을 묻지 않아, 원격에는 있지만 이 클론이 아직 받아 오지 않은 브랜치면 뒤처진 기준으로 워크트리가 만들어졌다(WT-03 우회). 비차단: 원격에서 지워졌는데 추적 참조가 남은 브랜치는 두 방식 모두 실패해 오도 가도 못 함, 오류 문구 비교가 언어 설정에 따라 빠질 수 있음, SKILL.md "하는 일" 문단·WT-03 본문 미반영.

**고친 것:** `--local-base`도 `git fetch origin <base>`를 실행하고 "couldn't find remote ref"일 때만 진행한다. 받아 오기에 성공하면(원격에 있음) 거부, 다른 실패(로그인 만료 등)는 기본 모드처럼 멈춘다. 받아 오기는 `LC_ALL=C`로 실행해 문구 비교가 언어 설정과 무관하다. 낡은 추적 참조는 무시하고 알린다(정리는 사람 몫). `--base` 없는 `--local-base`는 기준 자동 결정보다 먼저 거부한다. SKILL.md·WT-03 본문 반영.

**2차: 통과.** T9(원격에만 있음) 거부, T10(원격에서 지워짐) 진행·안내, T10b 안내가 T10으로 이어짐, T2·T3·T5·T6·T7·T7b·한국어 설정·origin 없음·연결 불가, HEAD 스크립트와 출력 비교(종료 코드 모두 같음). 비차단 메모: `--local-base` 도움말이 옛 동작 문구 → 고침. 기본 모드의 받아 오기 오류도 영어로 나온다(동작 같음, 스크립트의 다른 메시지도 영어라 그대로 둠).
