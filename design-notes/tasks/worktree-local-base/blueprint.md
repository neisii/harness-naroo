# 청사진 — worktree 스킬: 로컬 기준 브랜치와 메트릭 원장 없음

> 작성: 2026-11-21. 근거: 관문 3 실전 기록(`../release-0.2.0/gate3-관측기록.md`) 고칠 거리 ⑤, 그리고 ①(WT-16 ① 조건화)에 맞춘 스크립트 지원.

## 문제

1. **기준 브랜치가 원격에 없으면 워크트리를 못 만든다.** gate3에서 후속 작업(W2PC·W3PC)을 아직 push하지 않은 W1 브랜치 위에 쌓으려 하자, 스크립트가 `git fetch origin <base>`에서 "couldn't find remote ref"로 멈췄다. 실무자는 WT-03대로 손으로 `git worktree add`를 하지 않고 멈췄고, 사람이 W1을 push한 뒤에야 진행됐다.
2. **메트릭 원장을 안 쓰는 팀도 `PRJ_METRICS_DIR`가 늘 기록된다.** 규칙(WT-02 4번·WT-16 ①)은 이제 "메트릭 원장을 쓰는 팀만"인데, 스크립트에는 끄는 방법이 없다.

## 바꾸는 것 (`skills/worktree/new_worktree.py`, `SKILL.md`)

| 옵션 | 동작 | 막는 것 |
|---|---|---|
| `--local-base` | `git fetch`와 뒤처짐 검사를 건너뛰고 로컬 기준 브랜치에서 만든다 | `--base` 없이 쓰면 실패. 원격 추적 브랜치(`origin/<base>`)가 있으면 실패 — 그때는 평소대로 뒤처짐 검사를 받아야 한다 |
| `--no-metrics` | `PRJ_METRICS_DIR`를 기록하지 않는다(메트릭 폴더도 안 만듦) | — |
| fetch 실패 안내 | "couldn't find remote ref"면 `--local-base`나 사람에게 push 요청을 안내하고, 손으로 만들지 말라고 덧붙인다 | — |

자동 대체(원격에 없으면 알아서 로컬로)는 하지 않는다. 일부러 로컬에만 둔 것인지, 이름을 잘못 쓴 것인지 스크립트는 모른다. 그래서 옵션으로 의도를 밝히게 한다.

## 바꾸지 않는 것

- 기본 동작(옵션 없이 실행)은 그대로다.
- 커밋·push·삭제는 여전히 하지 않는다.

## 시험 계획

임시 bare 원격 + 클론에서: ① 원격에 없는 기준 + 옵션 없음 → 실패와 안내 ② `--local-base` → 성공 ③ `--local-base`만(기준 없음) → 실패 ④ 원격에 있는데 `--local-base` → 실패 ⑤ `--no-metrics` → 성공, 설정 파일 없음 ⑥ 기본 동작 회귀.
