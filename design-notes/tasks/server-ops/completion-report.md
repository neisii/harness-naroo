# server-ops 완료보고서

> 작성: 2026-11-20. 청사진: [`blueprint.md`](./blueprint.md) (2026-11-20 사용자 승인).
> 양식: 규칙 5단계 CM-02. 작업이 화면이 아니라 스킬이라, API·DB·화면 변경 항목은 "해당 없음"으로 둔다.

## 구현 내용

- 공개판 스킬 `server-ops`를 새로 만들었다. **Spring Boot + Gradle 프로젝트 전용.** 하위 명령 `init`·`build`·`start`·`stop`·`status` 다섯.
- 공용 실행기 하나가 설정 파일(`.claude/harness-servers.json`)을 읽어 실행한다. 프로젝트별 스크립트 파일은 만들지 않는다.
- 적용 판단(청사진 0절): `init`이 Gradle 래퍼·Spring Boot 플러그인·JDK를 확인하고, 하나라도 맞지 않으면 설정 파일을 만들지 않고 "환경 차이로 실행할 수 없다"고 안내한 뒤 종료 코드 2로 끝낸다. SKILL.md에도 AI 세션이 쓰기 전에 같은 대조를 하라는 가이드를 넣었다.
- 규칙 WT-10·11·12와 체크리스트, rules/00, `docs/환경값-정의.md` C를 `server-ops`에 맞췄다.

**청사진에 규정이 없어 구현 중 정한 것** (구현 담당 서브에이전트가 정함, 검수에서 그대로 둠)
- `init`의 인터페이스: `init --name X --port N [--health URL] [--write] [--force]`. `--write`가 없으면 후보 JSON만 출력한다. 설정 파일이 있으면 `--force` 없이 덮어쓰지 않는다(`--force`면 서버 한 건을 병합).
- `start --ignore-memcheck`: 메모리 경고(종료 코드 4)를 **사람이 승인한 뒤에만** 넘기는 용도. `start --timeout`(기본 120초).
- 종료 코드: 0 정상, 1 오류, 2 init 적용 불가, 3 포트 점유, 4 메모리 경고, 5 기동 실패·시간 초과. `build`는 빌드 명령의 코드를 그대로 낸다.
- `--dir`는 워크트리 루트로 보고 `<--dir>/<서버 dir>`에서 실행한다. 기록 폴더는 설정 파일이 있는 프로젝트 루트의 `.claude/server-ops/`에 포트별로 남는다. 서버가 하나뿐이면 이름을 생략할 수 있다.
- `start`는 구동 명령을 셸로 실행하고, POSIX에서는 새 세션의 프로세스 그룹을 통째로 종료한다(실제 `gradlew bootRun`에서 앱까지 종료됨을 확인). 종료 뒤에도 포트가 열려 있으면 경고와 함께 종료 코드 1.
- 즉시 종료하거나 시간을 넘긴 기동은 띄우다 만 프로세스를 종료하고 PID 파일을 지운다.

## 새 맥락 재검증 (2026-11-20)

이 세션의 맥락을 물려받지 않은 검증자를 띄워 청사진·이 보고서·규칙 1·5·11·12단계와 대조하게 했다. 6항목 중 4항목 통과, 2항목(안전성, 규칙 정합) 실패. 실패 원인은 고쳤다.

| 찾은 것 | 조치 | 다시 확인 |
|---|---|---|
| 낡은 PID 파일이 관계없는 프로세스를 가리키면 `stop --yes`가 그 프로세스를 종료함(PID 재사용) | 종료 대상에 그 PID의 명령 줄을 보여 줌. 포트는 닫혔는데 PID만 살아 있으면 `--yes`여도 종료하지 않고 사람에게 넘김(종료 코드 1) | 무관한 `sleep`을 가리키게 하니 종료하지 않음 |
| 서버 이름에 `..`을 넣으면 기록 폴더 밖 파일을 지움 | 이름을 영문·숫자·`.`·`_`·`-`로 제한하고 `..` 거부. 기록 파일 경로가 기록 폴더 안인지 확인 | `../../victim` 거부(종료 코드 1) |
| SKILL.md가 "명령을 그대로 실행"이라고만 적음 | "셸로 실행하므로 설정 파일 변경은 코드 변경처럼 검토"를 추가 | — |
| 규칙 12단계에 옛 이름 `server-status`가 남음 | `server-ops status`로 교체 | — |
| 규칙의 헬스 GET 설명이 코드와 다름(`/`에 GET) | "등록된 헬스 URL에 GET 1회(없으면 보내지 않음)"로 교체 | — |
| WT-11 표의 종료 줄에 `--dir`가 없어, 워크트리 서버 대신 본 폴더 서버를 대상으로 잡을 수 있음 | 종료 줄에 `--dir`·`--port`와 주의 문구 추가. 체크리스트도 "구동·종료 모두 `--dir`" | — |

함께 고친 작은 것: Windows의 PID 확인을 부분 문자열이 아니라 정확한 일치로, `status`의 `git status`가 저장소 색인을 건드리지 않게 `--no-optional-locks`.

남은 위험(고치지 않음): 포트가 열린 상태에서 PID가 다른 프로세스에 재사용된 경우는 막지 못한다. 종료 대상에 명령 줄을 보여 주므로, 사람이 `--yes` 전에 확인한다.

남겨 둔 보완 권고(이번에 고치지 않음): Spring Boot 판정이 문자열 포함이라 주석에만 있어도 통과함, 커밋이 없는 저장소를 "git 저장소 아님"으로 표시함, Windows `subprocess`의 출력 인코딩 미지정.

## 미검증 사항

- **Windows:** 작업 환경이 macOS라 Windows에서는 검증하지 않았다(`gradlew.bat`, `taskkill /T` 경로).
- **메모리 경고 경로:** 실제로 메모리가 부족한 상황이 아니라, 스크래치에 복사한 스크립트와 가짜 memcheck로 경고를 만들어 확인했다.

## 후속 작업

- `plugin.json` 버전 올리기는 0.2.0 출시 작업에서 한다.
