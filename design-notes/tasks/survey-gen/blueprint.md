# survey-gen 청사진

> 상태: 승인됨 (2026-11-20 작성, 같은 날 사용자 승인)
> 양식: 규칙 3단계 RQ-07의 6개 항목. 작업 단위가 화면이 아니라 스킬이라, 환경값 E에 따라 "화면 → 동작", "API → 명령 인터페이스"로 바꿔 읽는다.

## 배경

- 규칙 2단계 RL-12는 사람에게 물을 결정을 모아 `survey-gen`으로 만든 HTML 설문으로 한 번에 묻게 한다. 8단계 AR-16은 그 파일 이름과 위치(`<공유문서 루트>\지시대기\`)를 정한다.
- `survey-gen`은 원본 SI 전용이라 공개판에 없다.
- 원본(`survey_gen.py` 352줄, `template.html`, `index_template.html`)을 분석했다. 같은 폴더의 `index-refresh`·`blueprint-index`·`docs-consolidate`·`md2html`은 survey-gen과 같은 방식을 쓰거나 그 결과를 소비하는 원본 SI 전용 도구라, 이번 범위에 넣지 않는다.

**원본에서 가져오는 것**
- 입력 JSON 형식(문항마다 번호·제목·배경·선택지·권고안과 이유·보류 작업)과 입력 검증
- 설문 HTML의 기능: 선택 버튼, 메모, 권고안 일괄 선택, 답변 생성·복사, 미응답 문항 표시, 브라우저에 진행 상태 저장, 다크 모드
- 답변 텍스트 형식(아래 2절). `record`가 이 형식을 읽는다.
- 인덱스는 내용이 바뀔 때만 다시 쓰기

**원본에서 바꾸는 것 (관리 체계를 새로 짠 이유)**
- 원본은 상태를 파일 위치로 나타냈다. 답한 설문을 `완료설문\` 폴더로 옮기고, 응답 md를 따로 만들었다. 같은 설문이 두 폴더에 흩어졌고, 옮긴 뒤 번호가 충돌한 사고가 있었다.
- 문항을 다른 설문으로 옮긴 사실을 별도 CSV(`이동표시.csv`)로 관리했다.
- 경로가 원본 SI 폴더 구조에 고정돼 있었다.

## 1. 동작

| 하위 명령 | 하는 일 |
|---|---|
| `new --input <질문.json>` | JSON을 검증하고, 설문 폴더와 `survey.json`·`survey.html`을 만든다. 검증에 실패하면 아무것도 만들지 않는다 |
| `record <설문ID> --input <답변.txt>` | 사람이 붙여 넣은 답변 텍스트를 문항 번호와 대조해 `answers.md`에 저장하고, 상태를 "응답됨"으로 바꾼다. 빠진 문항·없는 번호·선택지에 없는 답을 알린다 |
| `close <설문ID> --note "<반영한 곳>"` | 상태를 "반영 완료"로 바꾸고, 결정을 반영한 곳(커밋·문서)을 적는다 |
| `index` | `index.md`를 다시 만든다. 다른 명령을 실행하면 자동으로 함께 갱신된다 |

상태 흐름: **미응답 → 응답됨(`record`) → 반영 완료(`close`)**. 파일을 옮기지 않는다.

`record`의 입력은 세션이 받는다. 사람이 설문 HTML에서 "답변 생성 → 복사"한 텍스트를 세션에 붙여 넣으면, 세션이 그 텍스트를 파일로 저장한 뒤 `record`를 실행한다.

## 2. 데이터

**폴더 구조** (설문 루트 기본값 `docs/surveys/`, 환경값)

```
docs/surveys/
  index.md
  2026-11-20-01-<짧은 이름>/
    survey.json
    survey.html
    answers.md
```

- 폴더 이름 = 날짜 + 그날의 순번(2자리) + 짧은 이름. 짧은 이름은 입력 JSON의 `slug`에서 가져오고, 없으면 생략한다.
- 순번은 설문 루트의 기존 폴더를 보고 정한다. 폴더를 옮기지 않으니 순번이 충돌하지 않는다.

**`survey.json`** = 입력 JSON + 관리 칸

```json
{
  "title": "설문 제목",
  "note": "(선택) 상단 안내",
  "slug": "(선택) 폴더 이름에 붙일 짧은 이름",
  "items": [
    {
      "id": "1",
      "title": "문항 제목",
      "background": "배경",
      "options": [{"key": "A", "label": "..."}, {"key": "B", "label": "..."}],
      "recommend": "A",
      "recommendReason": "(선택)",
      "hold": "(선택) 응답 전까지 보류되는 작업",
      "movedTo": "(선택) 이 문항을 옮긴 설문ID"
    }
  ],
  "status": "미응답 | 응답됨 | 반영 완료",
  "createdAt": "YYYY-MM-DD HH:MM",
  "answeredAt": "",
  "closedAt": "",
  "closeNote": ""
}
```

- 관리 칸(`status` 이하)은 스킬이 채운다. 사람이나 세션이 입력 JSON에 넣지 않는다.

**답변 텍스트 형식** (원본 템플릿과 같음)

```
[<설문 제목> 응답]
1. <문항 제목> → A. <선택지>
   메모: <메모>
2. <문항 제목> → (선택 없음)
   메모: <메모>
미응답: 2
```

**`index.md`** — 상태·제목·문항 수·만든 날·설문 링크·답변 링크·비고(옮긴 문항 등)를 한 표에 모은다. 미응답을 맨 위에 둔다. 원본의 html 보기 화면은 만들지 않는다(2026-11-20 결정).

## 3. 명령 인터페이스

```sh
python3 "${CLAUDE_PLUGIN_ROOT}/skills/survey-gen/survey_gen.py" <하위명령> [...] [--root <설문 루트>]
```

- Windows는 `python3` 대신 설치된 Python 명령(`python`, `py`)을 쓴다.
- `--root`가 없으면 `./docs/surveys/`를 쓴다.
- Python 표준 라이브러리만 쓴다.

## 5. 결정사항 (2026-11-20 사용자 결정)

- `지시대기` 체계를 가져오지 않고 관리 체계를 새로 짠다.
- 설문 루트 기본값은 `docs/surveys/`.
- 인덱스는 `index.md`만 만든다.
- 설문 하나 = 폴더 하나, 상태는 `survey.json`에서 관리, 하위 명령은 `new`·`record`·`close`·`index`.
- 스킬 이름은 `survey-gen`을 유지한다(규칙의 언급과 맞춤).

## 6. 미확정사항

- **공개 전 점검:** 원본 코드를 바탕으로 하므로, 커밋 전에 기밀 토큰 점검(push 전 hook과 같은 기준)과 원본 경로·세션 이름(qa-master 등 환경값 제외) 잔존 여부를 확인한다.
- **Windows 검증:** 작업 환경이 macOS라 Windows에서는 검증하지 않는다. 완료보고서에 그렇게 적는다. 파일 입출력만 쓰므로 OS 차이는 작을 것으로 본다(추정).

## 검증 계획

- 예시 JSON으로 `new` → HTML을 브라우저로 열어 선택 → 답변 생성 → 복사가 되는지 확인한다(Chrome DevTools로 확인).
- 복사한 텍스트로 `record` → `answers.md`와 상태가 맞게 바뀌는지, 빠진 문항·없는 번호를 알리는지 확인한다.
- `close` → `index.md`가 갱신되는지, 내용이 같으면 다시 쓰지 않는지 확인한다.
- 잘못된 입력(선택지 1개, 권고안이 선택지에 없음, 번호 중복)에서 아무것도 만들지 않는지 확인한다.
- 완료 전 새 맥락 재검증(`dlc-gate`의 독립 재검증)을 거친다.
