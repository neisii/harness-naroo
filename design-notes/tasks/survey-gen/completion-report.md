# survey-gen 완료보고서

> 작성: 2026-11-20. 청사진: [`blueprint.md`](./blueprint.md) (2026-11-20 사용자 승인).
> 양식: 규칙 5단계 CM-02. 작업이 화면이 아니라 스킬이라, API·DB·화면 변경 항목은 "해당 없음"으로 둔다.

## 구현 내용

- 공개판 스킬 `survey-gen`을 새로 만들었다. 하위 명령 `new`·`record`·`close`·`index` 넷.
- 설문 하나 = 폴더 하나(`<설문 루트>/<날짜>-<순번>[-이름]/`), 상태는 `survey.json`에서 관리, 파일을 옮기지 않는다.
- 원본 SI의 `survey_gen.py`에서 입력 검증과 "내용이 같으면 쓰지 않기"를 가져왔다. 설문 HTML 템플릿은 원본을 그대로 쓰되, 원본 경로가 든 머리 주석만 걷어 냈다. 답변 텍스트 형식은 원본과 같다.
- 규칙(RL-12·AR-16·rules/00)과 `docs/환경값-정의.md`를 새 체계에 맞췄다.

**청사진에 규정이 없어 구현 중 정한 것** (구현 담당 서브에이전트가 정함, 검수에서 그대로 둠)
- `record`는 이미 "반영 완료"인 설문이면 거부한다. "응답됨" 상태에서 다시 `record`하면 `answers.md`를 덮어쓴다.
- `close`를 "미응답" 상태에서 하면 경고를 내고 닫는다.
- `index.md` 비고에 옮긴 문항(`movedTo`)과 함께 반영한 곳(`closeNote`)도 적는다.
- 설문이 하나도 없으면 `index.md`를 만들지 않는다.

## 새 맥락 재검증 (2026-11-20)

이 세션의 맥락을 물려받지 않은 검증자를 띄워, 청사진·이 보고서·규칙 5·8·11·2단계와 대조하게 했다. 결과 6항목 중 4항목 통과, 2항목 실패. 실패 원인은 모두 고쳤다.

| 찾은 것 | 조치 | 다시 확인 |
|---|---|---|
| 템플릿 머리 주석 안에도 자리표시자가 있어, 설문 데이터가 주석에 한 번 더 들어감. 데이터에 `-->`가 있으면 주석이 닫혀 HTML이 깨질 수 있음(원본에서 이어받은 결함) | 주석에서 자리표시자 글자를 빼고, 자리표시자가 정확히 한 번 있는지 확인하게 함 | 머리에 데이터 0줄, 남은 자리표시자 0 |
| 번호를 정수로 넣으면 `record` 대조가 어긋나 가짜 경고 2건 | `new`에서 번호를 문자열로 맞춤 | 정수 번호 설문에 경고 없음 |
| 다시 `record`해도 출력이 늘 "미응답 -> 응답됨" | 실제 이전 상태를 출력 | "응답됨 -> 응답됨" |

## 미검증 사항

- **Windows:** 작업 환경이 macOS라 Windows에서는 검증하지 않았다.
- **클립보드 복사:** `file://`로 연 페이지는 보안 맥락이 아니라 브라우저가 대체 복사 방식을 쓴다. 답변 텍스트가 결과 칸에 만들어지는 것은 확인했지만, 실제 클립보드에 들어갔는지는 확인하지 않았다.
